# UI 与信息架构审查

## 产品定位

- 这是批量调度系统控制台，不是营销站。界面应偏运维、数据密集、可扫描、可比较、可重复操作。
- 第一屏优先呈现用户要处理的对象、状态和操作，不用大 hero、装饰卡片或过度留白。
- 桌面端承载主要操作；移动端是轻量查看和应急操作入口，业务逻辑尽量复用桌面。

## 审查入口

1. 从 `src/router/index.ts`、`src/constants/navigation.ts`、页面 meta、布局和代表性页面开始，先看 IA 再看单个组件。
2. 表格页面检查筛选、排序、分页、批量操作、空态、错误态、列密度和详情跳转。
3. 表单/设计器检查字段分组、默认值、依赖关系、校验时机、撤销/保存/发布边界和后端契约。
4. 对审批、批量日、Worker、文件到达、Outbox、报表等运维页面，优先保证状态可读、动作可追踪、异常可定位。

## 设计系统约束

- 优先使用 Element Plus、已有 `src/components/common` 和 design token。
- 避免裸 hex/裸 px、重复造下拉/弹窗/表格、卡片套卡片和文案塞满按钮。
- 图标按钮使用已有图标库并提供 tooltip 或可访问名称。

## 验证

- UI 改动至少检查桌面常见宽度、窄屏、长文本、空数据、大数据和错误态。
- 有截图或 Playwright 证据时说明 viewport、数据来源和是否连真实后端。
