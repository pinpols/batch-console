# UI、交互与视觉审查

## 定位与来源

批量调度控制台以任务清楚、信息可扫描、操作可追踪为目标。桌面承载主要操作，移动端保留轻量查看/应急场景；根据现有产品定位评估层级、密度、留白与视觉一致性。

- 设计与交互以 [design token](../../../docs/engineering/design-tokens.md)、[交互约定](../../../docs/engineering/ui-interaction-conventions.md)、现有 Element Plus/共享组件及页面任务为准。运行时 token 来源是 `src/styles/tokens-handoff.css`，`design/` 历史交付稿不自动成为当前规范。
- 完整常见问题及反例见[UI与交互检查表](references/common-ui-checks.md)。按页面和改动选择适用项；全站任务先固定页面/流程分母，不能用少量截图宣称全站完成。
- 本技能维护UI/交互/视觉的具体检查；代码级Bug或跨领域审查使用 `frontend-quality-review`，纯代码规约/门禁使用 `frontend-engineering-governance`，文案/语义可访问性使用 `frontend-i18n-accessibility`，异步与契约按需进入各专项。共享证据，不重复跑同一页面。

## 审查步骤

1. 明确页面任务、用户角色、租户/对象、路由与深链、关键操作及运行版本；从路由/导航、布局、共享组件追到实际页面。保留现有数据和编辑状态，造数/删除/发送等动作依用户授权。
2. 使用检查表核对正常、加载、空、错、权限、提交中和部分结果等实际适用状态；选择影响最大的主题、语言、密度和视口组合，不机械执行所有组合。
3. 视觉和交互结论优先来自实际页面：保留必要截图/局部图、DOM及computed style、键盘/操作步骤，记录 viewport、缩放、主题、Locale、角色、数据来源和服务/构建身份。仅源码/静态资料评审时标明“待浏览器复核”。
4. 操作沿选中对象、请求目标、服务端结果与页面反馈核对；截图、toast或按钮点击不能证明业务成功。复杂图表/DAG同时检查真实文字、状态、数据缺失与安全渲染。
5. 修复后在同角色/视口/主题/数据条件对比；共享组件及token修改追代表调用方及相关窄屏/弹层状态。视觉变化按现行design token规范执行适用视觉回归，测试入口由 `frontend-testing-ci` 选择。

## 发现与交付

- **功能Bug**：可观察的错误目标、错误状态、数据/权限/提交行为，给出预期、实际、触发和因果证据，交质量审查统一记录。
- **可用性/可访问性问题**：目标操作无法发现、读懂、完成或通过键盘完成，说明用户任务和具体障碍。
- **视觉/一致性问题**：指出与当前token/组件/交互约定的偏差及实际影响；有意设计差异按其依据保留。
- **视觉建议**：纯偏好或尚无规范/任务证据的改进明确为建议，不包装成Bug或强制改造。
- 每项保留页面/组件位置、角色/状态、证据、影响、建议和验证状态；历史截图、axe节点次数、预测分数与未执行场景不能冒充当前验收。
