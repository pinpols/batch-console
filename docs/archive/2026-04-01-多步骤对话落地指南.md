# 批量调度控制台 — 多步骤对话落地指南

本文档用于 **分多轮对话（或与 AI 结对编程）** 把 `batch-console` 从当前骨架推进到可交付状态。每一「步」可单独新开对话或在同一线程连续执行；**每步结束时**应满足列出的验收标准，再进入下一步。

## 如何使用「多步骤对话」

1. **一步一做**：完成当前步验收后再开新对话做下一步，减少上下文丢失。  
2. **每轮给 AI 的固定前缀**（可复制）：

```text
请严格按本仓库 docs/多步骤对话_V3.md 第 N 步执行；只改必要文件；对齐 docs/api/console-api.openapi.yaml；改完运行 npm run build。
```

3. **每步交付物**：代码 + 若涉及新环境变量，更新 `.env.development` 说明（不写无关文档）。  
4. **联调约定**：开发环境 `VITE_API_BASE_URL` 为空时走 Vite 代理 `/api`；租户以顶栏 `tenantId` + `X-Tenant-Id` 为准。

## 后端待确认 / 增强（文档记录，联调时核对）

以下项 **不阻塞前端构建**，但与真实后端对齐时建议逐项确认（**以当前 OpenAPI 与线上后端为准，不一致时先改契约再改前端**）：

1. **`PageResponse` 与端上聚合**：当前 OpenAPI 中大量 query 的 `data` 已为 `PageResponse`。前端对 **需端上筛选** 的列表使用 `fetchAllPageItems` 多页拉齐（有 `maxPages`/`pageSize` 上限）；超大数据量时的性能与超时需联调评估。  
2. **筛选参数**：`instances`、`workflow-runs`、`files` 等 **OpenAPI 未声明 jobCode、definitionId、文件名等 query 时**，有筛选则走全量聚合再分页；后端若补充筛选参数，应改为直连服务端分页并删掉多余聚合。  
3. **`job-step-instances` / `PartitionView`**：按实例过滤依赖聚合后的客户端过滤；若后端增加 `jobInstanceId` query 应改为服务端过滤。  
4. **Excel multipart**：上传字段名约定为 `file`；`uploadToken` 及 preview 路径与真实 Controller 是否一致需联调确认。  
5. **报表下载**：错误时若返回 JSON 而非 blob，浏览器无法打开文件——依赖 `Content-Type` / 错误体约定。  
6. **审批状态枚举**：协议（`console-api-protocol.md`）说明勿假定 `CLOSED`/`CANCELLED` 为审批终态；`ApprovalList` 若仍含旧集合，联调时按后端枚举修正。  
7. **执行日志**：OpenAPI 无独立 execution-log 查询，当前用 **`query/audits` 代替**；若有专用日志 API，应改路由与字段。  
8. **告警治理**：已接 `POST …/alerts/{id}/ack|silence|close`（`AlertActionRequest`）；静默时长等若后端另有字段，以 OpenAPI 为准再扩展表单。  
9. **治理配置新接口**：`QuotaPanel` / `QueueConfig` 已接 `GET /api/console/quota-policies`、`GET /api/console/queues`、`GET /api/console/batch-windows`、`GET /api/console/calendars` 以及对应 `toggle` 命令；create/update/holiday 写接口仍待补表单或专页。  
10. **`query/workflow-topology`**：类型已与契约一致；`WorkflowDesigner` **仍以 nodes+edges 拼 DAG**，未把 topology 中的 runs 叠加进画布（可选增强）。  
11. **新增查询页已补齐一批**：`query/catch-up-approvals`、`query/file-templates`、`query/ai-audits` 已有对应前端入口；其余如更多 dashboard 细分交互可继续增强。  
12. **Pipeline 定义**：已补列表 / detail / toggle / create / update 的前端入口；由于 OpenAPI 对写入体仍是宽泛对象，当前表单采用显式基础字段 + `stepsJson` 组合编辑，后续以后端补齐 schema 为准收紧。  
13. **Dashboard 图表**：`OpsSummary` 已优先消费 `dashboard/job-stats`、`trigger-stats`、`worker-load`、`alert-trend`、`sla-compliance`，减少依赖 query 近似聚合。  

**说明**：验收以 `npm run build`、路径与 **当前仓库 OpenAPI** 一致为准；**联调以后端实际响应为准**。
