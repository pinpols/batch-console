# Console 维护与降级

> 文档职责：持续维护的当前设计、契约与验收边界；原始形成基线为 2026-09-29，原批次验证仍按正文日期解释。当前实现修改时维护本文件，新的联测结果另存日期记录。

> 文档性质：当前实现记录与验收边界，不是未完成施工清单。前端维护状态、写操作冻结、503 回跳和降级提示已落地；剩余内容仅表示真实设备或外部下游环境验收边界。

## 1. 范围

本方案配套后端维护与降级契约，目标是让 Console 在维护窗口和下游服务异常时：

- 给用户明确、可恢复的状态；
- 禁止用户继续提交不可靠的写操作；
- 区分“系统维护”“下游降级”和“真实空数据”；
- 在桌面端和移动端保持一致。

不新增通用编排、工单、服务网格或独立通知平台能力。

## 2. 当前实现与缺口

> 2026-10-13 状态：本分支补入计划停机 `startsAt`、服务端权威 `active` 判定、公告倒计时和到点拦截；并为 Worker、批次回放、审批、Outbox 补救、调度器及部分系统管理写按钮补维护态禁用。Axios 拦截器仍是所有写请求的最终前端兜底，后端维护过滤器是最终安全边界。**所有页面写按钮的穷尽式 UI 覆盖尚未验收**，不能将局部按钮禁用描述为全站每个按钮均已灰显。其余既有降级真实环境验收边界见下文。

## 3. 前端改造顺序（历史实施记录）

### P0：维护窗口可用性

1. 已完成：扩展维护状态模型，包含 `version`、`updatedAt`、`lastSyncedAt`、`syncError`、`isStale`。
2. 已完成：收敛 `useMaintenancePolling`，维护期 10 秒、正常期 30 秒，失败保留最近状态。组件卸载后忽略在途成功/失败回包。轮询、管理操作和响应头共用的 Store 拒绝旧配置版本；同版本允许计划维护到点生效，但不能被较早的待开始快照撤销。恢复或改期由新配置版本表达。修复与回归见[Bug 治理记录](../reports/2026-10-26-frontend-bug-remediation.md)。
3. 已完成：建立统一 `useWriteAvailability`，并接入本轮确认的写按钮；全站视觉禁用覆盖仍需按写 API 清单继续验收。
4. 已完成：拦截维护 503 后进入 `/maintenance`，保留安全的原始路由。
5. 已完成：维护恢复后回跳，回跳失败返回安全首页。

### P1：降级可解释性

1. 已完成：根据 `X-Degraded-Source` 展示非阻塞 Banner。
2. 已完成：空列表 fallback 显示下游不可用提示，不显示为普通空数据。
3. 已完成：正常响应、超时、降级、恢复分别维护明确状态。
4. 已完成：统一中英文文案、长文本、无 ETA、跨时区 ETA 的展示。
5. 已完成：桌面和移动布局使用同一 store 和状态语义；真实设备验收仍保留为环境边界。

## 4. 后端契约依赖

后端是契约权威，前端只消费以下字段和响应头：

```text
GET /api/console/system/maintenance
PUT /api/console/admin/system/maintenance
X-Maintenance
X-Maintenance-Version
X-Degraded-Source
Retry-After
```

维护 503 body 至少包含：

```text
maintenance
readOnly
message
etaAt
startsAt
active
affectedServices
version
```

后端未提供 `X-Degraded-Source` 前，前端不能把普通 5xx 或空响应推断为降级。

## 5. 测试与验收

### 单元与组件

- maintenance store 更新、版本覆盖和过期状态；
- 轮询成功、失败、恢复；
- 写操作守卫在全冻结/只读/正常三态下的行为；
- 503 解析和即时导航；
- 降级来源合并、TTL、恢复清除。

### E2E

- 管理员开启全冻结，普通用户从业务页操作后进入维护页；
- 管理员切换只读，读页面可用、写按钮禁用、后端仍拦截写请求；
- 关闭维护后页面自动恢复；
- Trigger / Orchestrator 读接口 fallback 时显示来源 Banner；
- 多语言、移动端和长公告布局不溢出。

### 不纳入本方案

- 不测试或实现新的编排模式；
- 不把故障注入做成前端操作台；
- 不增加独立通知、工单、告警管理产品。

## 6. 完成定义

- 所有重点写页面接入统一写保护；
- 维护 503 可以立即进入维护页并安全恢复；
- 降级不会伪装成真实空数据；
- 后端 OpenAPI、前端生成类型、拦截器、Banner、E2E 文案一致；
- 桌面端和移动端均通过验收。

## 2026-10-26 维护通知边界

维护设置帮助文案同步后端定向抑制：`affectedServices` 仍作为公告展示，识别的固定应用编码同时限定计划停机通知范围。留空只针对 Console；未知标记不静默，也不会执行服务启停或改变业务路由。ETA 为空时通知窗口默认 2 小时，最长 24 小时；后台重试不会自动延长，窗口到期只恢复告警通知，不解除业务冻结。

此功能需部署 Alertmanager 控制信号及同范围抑制规则，不能以页面保存成功表示通知已被抑制。配置、指标、传播延迟与验证边界以配对后端[维护 SOP](../../../file-batch-system/docs/runbook/maintenance-mode.md#10-维护期通知抑制2026-10-26)为准。本轮修改帮助文案，不宣称完成真实移动设备或站点维护联验。
