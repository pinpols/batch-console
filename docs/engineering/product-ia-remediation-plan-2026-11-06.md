# 产品信息架构整改方案（2026-11-06）

状态：方案已确定，待实施；其中 4 项需产品决定，已给出推荐默认值。来源为[产品层面功能重叠与信息架构审查](../audits/ui-ux/product-ia-review-2026-11-06.md)的 P1–P10。本文是这些整改的范围、核实结果、分批、验收和进度的唯一主记录；审查记录只保留发现。

## 目标

1. 同一用户任务只有一个主入口，重复页面合并或明确分工。
2. 侧栏隐藏的页面都能从界面点到，不再只能靠 ⌘K 搜索；各角色可见菜单数量不增加或基本持平。
3. 修复审查核实中发现的权限与落点缺陷。
4. 桌面与移动端审批的组织方式一致。

## 核实结果（2026-11-06）

审查时标为“待核实”的项目已逐项对照前端源码和配对后端源码核实，结论如下。新发现的缺陷已并入对应整改项。

| 项 | 核实内容 | 结论与依据 |
| --- | --- | --- |
| P1 | `/runs` 的内容与入口 | `RunsOverview.vue` 展示今日完成/失败/等待计数与最近作业、工作流运行各一段，带“查看全部”跳转；与控制面板今日计数、两张运行列表重叠。除导航和路由定义外无任何页面链接 |
| P2 | 两页的入口 | 顶栏用户菜单“个人”一项打开的是 `/system/users`（权限自查）。“我的账户” `/system/me`（含修改密码）没有任何菜单或用户菜单入口，只能通过改密提醒横幅或 ⌘K 进入。**缺陷：用户无法主动找到修改密码** |
| P3 | 审计页权限 | 文件审计与操作审计路由权限相同（平台管理员、租户管理员、审计员），合并为同一页签页不需要额外的页签级权限 |
| P4 | 告警相关页面权限 | 资产新鲜度 `OPERATOR`；作业监控策略限平台/租户管理员；告警路由仍被作业定义详情 `JobDefinitionDetail.vue` 链接 |
| P6 | 触发器页与工作流调度是否同源 | **同源，无状态冲突**。后端 `batch-trigger` 的 `TriggerRegistrationService` 中，注册与恢复都是把工作流 `schedule_enabled` 置为 true 再注册 Quartz，注销与暂停都是删除 Quartz 再置为 false，两组实现相同；`TriggerReconciler` 每 30 秒按数据库收敛 Quartz。问题是同一开关有四个按钮、三个入口 |
| P7 | 自助服务后端角色与审批 | 后端自助接口（配额、重跑申请、补偿申请）允许平台管理员、租户管理员、租户用户调用。审批批准逻辑（orchestrator `markApproved`）不校验审批人是否为申请人，仅配置发布审批禁止自批；管理员可以自己申请再自己批准。**缺陷：“暂停触发器”卡片直接调用 `/api/console/ops/triggers/{code}/pause`，该接口后端为 `ADMIN_ONLY`，而卡片对租户管理员、租户用户可见且未禁用，提交必然 403** |
| P9 | 移动端审批角标与落点 | 底栏审批角标取控制面板汇总 `pendingApprovals`，即 `approval_command` 中所有待审批记录，已含有审批单的补跑申请。补跑审批记录同时出现在普通审批列表（桌面 `GeneralApprovalsTab` 与移动 `MApprovals` 都不排除 `CATCH_UP` 类型），同一单据在两个页签各显示一次。桌面链接 `/approvals?tab=catch-up` 在手机上落到 `/m/approvals`，该页不读取 `tab`，显示普通审批 |
| P8 | 隐藏页入口 | 10 个隐藏页面无任何页面内入口：`/runs`、`/ops/capacity-profile`、`/ops/worker-fingerprints`、`/ops/custom-task-types`、`/ops/shard-catalog`、`/ops/tenant-placements`、`/system/parameters`、`/system/tags`、`/system/atomic-task-types`、`/ops/asset-freshness`；`/observability/lineage` 只在侧栏高亮映射中出现。AI 助手已有全局 `AiAssistantLauncher` 入口 |
| — | 后端菜单结构 | `menu.yml` 含分组与菜单项；前端以其路径作为路由白名单，分组展示以前端 `navigation.ts` 为准 |

## 通用约束

- **旧链接不失效**：页面改为页签或收进中心页后，原路由保留为重定向，透传原 query 并带上目标页签参数；参照现有 `/config/sync`、`/scheduler/catch-up-approvals`。移动端深链映射 `MOBILE_DEEPLINK_MAP` 同步调整。
- **权限按原页面判断**：并入宿主页的页签和中心页卡片沿用原页面的 `minRole`、`authorities`；用户能进宿主页不代表能看到全部页签。前端判断只控制体验，后端授权不变。
- **前后端菜单同源**：新增或删除菜单路径时，先改后端 `batch-console-api/src/main/resources/menu.yml`，再改前端 `navigation.ts`；只调整前端分组、页签、链接时不改后端。
- **不删功能、不改接口**：除明确列出的后端改动外，只调整入口与组织方式。
- **测试先行**：缺陷类整改先写能表达用户可观察行为的测试并确认修复前失败；移动端新增专属行为补针对性测试。

## 各项整改

### P1 统一运行入口（需决定）

- **推荐**：下线 `/runs` 页面。今日计数已由控制面板提供，最近运行由两张运行列表提供。`/runs` 改为重定向到 `/monitor/job-instances`，⌘K 中移除该项。
- **备选**：保留并放到“运行监控”第一项，作业运行、工作流运行降为它的页签；改动大，需要重做两张列表的筛选与深链。
- 改动：`router/index.ts`、`navigation.ts`、`pageMeta.ts`、词条；后端 `menu.yml` 若含 `/runs` 同步删除。
- 验证：旧链接重定向测试；`routeInventory` 测试更新。

### P2 账户与权限页合并（含缺陷修复）

1. **先修缺陷**：顶栏用户菜单增加“我的账户”，指向 `/system/me`，排在第一项；原“个人”项改名为“权限与菜单”，或在第 3 步合并后删除。
2. 把 `UserRole.vue` 的登录状态、角色链、权限列表、可访问菜单树作为“我的账户”页的一个区块（或页签“权限”），复用现有组件，不复制实现。
3. `/system/users` 重定向到 `/system/me?tab=permissions`；从“平台管理”侧栏移除；后端 `menu.yml` 删除该路径。
- 验证：用户菜单可达测试；重定向测试；四个角色都能看到自己的权限区块。

### P3 审计入口

- 新建“审计”页（复用现有 `AuditList` 等组件），页签：操作审计（默认）、文件审计；执行日志保留在综合查询，页头提供跳转。
- 侧栏“文件审计”替换为“审计”，菜单数不变；`/observability/audits` 重定向到 `?tab=file`，`/observability/operation-audits` 重定向到 `?tab=operation`。
- 自助服务“我的操作记录”抽屉保留，增加“在审计中查看全部”链接（仅对有审计权限的角色显示）。
- 后端 `menu.yml`：新增 `/observability/audit`，保留 `/observability/audits` 与 `/observability/operation-audits`，直到前端重定向上线后再删旧路径。

### P4 告警配置归位

- 资产新鲜度并入“作业监控策略”页的页签；页签按资产新鲜度原权限（`OPERATOR`）显示，作业监控策略页签保留原限制。宿主页路由权限放宽到二者并集，页签各自校验。
- 告警路由（预留）：移除 `JobDefinitionDetail.vue` 中的入口；路由保留供审计查看，侧栏继续隐藏。后端落地运行时路由后再重新评估。
- 菜单名“作业监控策略”改为“告警策略”，与内容一致。

### P5 “调度资源”组整理

- 不新增分组（保留 7 组）。组内用 `el-menu-item-group` 分为两个小标题：**调度运行**（调度快照、批次日与窗口、触发器、Worker）、**资源规则**（业务日历、批次窗口、资源队列、租户配额）。
- 平台基础设施类隐藏页移出本组，按 P8 归入 Worker 页签、使用统计页签或平台设置中心页。
- 验证：侧栏快照测试与四角色菜单测试（租户管理员不应看到窗口、队列、配额）。

### P6 触发器页去重

- 后端已核实四个动作只操作同一个 `schedule_enabled`。前端把“注册/恢复”合并为“开启调度”，“注销/暂停”合并为“暂停调度”，每行只显示与当前状态相反的一个按钮。
- 每行增加“调度设置”链接，打开对应工作流的调度设置；Cron 等参数只在工作流调度设置中修改。
- 自助服务的“暂停触发器”卡片按 P7 处理。
- 不改后端；后端保留四个接口以兼容。

### P7 自助服务定位（含缺陷修复，部分需决定）

1. **先修缺陷**：“暂停触发器”卡片只对平台管理员显示（与接口 `ADMIN_ONLY` 一致）。租户角色若需要暂停能力，作为后端需求另行登记“暂停调度申请”审批类型，前端不先做。
2. **推荐（需决定）**：按角色区分卡片。租户用户保留全部申请类卡片；平台管理员、租户管理员的重跑、补偿、暂停卡片改为直达对应操作页（作业运行、触发器），不走申请。
3. “失败作业”卡片改为跳转到作业运行列表并带“失败”筛选，删除重复的抽屉列表。
4. **已定（审批中心）**：自助类审批（`SELF_SERVICE`）在审批中心禁止申请人点通过，与配置发布的交互一致。后端批准逻辑仍不校验审批人是否为申请人，接口层拒绝需在配对后端另行登记。拒绝仍允许。

### P8 隐藏入口分流

原则：隐藏不是问题，“只能靠 ⌘K 找到”才是问题。

| 处理方式 | 入口 | 菜单净变化 |
| --- | --- | --- |
| 保持隐藏，已有上游链接 | 作业步骤、编排设计器、配置批量导入、流水线观测、到达组、批次日重放 | 0 |
| 保持隐藏，补上游链接 | 血缘证据：在作业实例详情、链路诊断中有 `result_version` 或业务键处加入口 | 0 |
| 并为页签 | 操作审计（P3）；资产新鲜度（P4）；事件目录 → 通知与投递；容量画像 → 使用统计；Worker 指纹、自定义任务类型 → Worker；分片目录 + 租户分片 → 一个“分片”页 | 0 或 -1 |
| 平台设置中心页 | 路径 `/system/settings`。系统参数、标签管理、原子节点配置、维护设置、分片仍保留原路径，卡片按原页面权限显示 | 维护设置移入，净 0 |
| 移到用户菜单 | API Key（个人凭据，租户用户也可用）：放入顶栏用户菜单“我的 API Key”，自助服务卡片保留跳转 | 0 |
| 改为可见 | 运维诊断、租户配额（仅平台管理员） | 平台管理员 +2 |
| 已有全局入口 | AI 助手 | 0 |

结合 P1（-1，如采用推荐）、P2（-1），平台管理员可见菜单数基本持平，租户角色不增加。

### P9 移动端审批对齐（含缺陷修复）

1. **先修缺陷**：`MApprovals` 读取 `tab` query；`tab=catch-up` 时显示补跑审批。
2. `MApprovals` 顶部增加“普通审批 / 补跑审批”分段，读写 `tab`，取值与桌面一致；补跑分段复用 `MCatchUp` 的列表与操作，抽成组件。
3. `/m/catchup` 重定向到 `/m/approvals?tab=catch-up`，保留 PWA 推送与邮件旧链接；深链映射中 `/scheduler/catch-up-approvals` 改指向同一地址；控制面板补跑快捷入口同步。
4. **去重**：普通审批列表（桌面与移动）应排除 `CATCH_UP` 类型，补跑审批只在补跑页签显示。后端 [PR #1330](https://github.com/pinpols/file-batch-system/pull/1330) 已合并 `excludeApprovalTypes`（逗号分隔字符串）契约。前端从后端 main 的 OpenAPI 重新生成类型，桌面普通列表、待审批页签计数及手机所有状态列表和计数传 `excludeApprovalTypes=CATCH_UP`，由服务端过滤后分页；类型筛选下拉不提供补跑。补跑专用查询和控制面板全部待审批角标口径不变。
5. 角标口径不变：汇总已包含有审批单的补跑申请；没有审批单的补跑请求不可审批，不计入角标。

### P10 概览类页面分工

不合并。控制面板“今日”卡片链接到报表中心与使用统计；报表中心、使用统计、容量画像的页面描述写明各自用途，并互相链接。
