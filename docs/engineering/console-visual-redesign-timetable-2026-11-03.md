# 控制台视觉重设计：时刻表方向（2026-11-03）

## 背景与决定

2026-11-03 对控制面板、作业定义和工作流运行三页做实页审查（1440×900、深色、租户 ta），主要问题：

- 字号偏小且层级平：正文 13px、表格 12px、表头 11.5px、状态标签 11px，标题与正文差距小。
- 深色底近黑、次级文字与卡片对比弱；卡片与背景几乎同色，只靠细边框区分。
- 颜色无语义：作业类型标签使用五六种颜色；状态标签沿用 Element Plus 默认派生色（如 `#67C23A`），未跟随项目 token。
- 字体混用：正文 IBM Plex Sans，标签使用等宽字体。
- 首页 11 张等大指标卡多为 0，看不出该处理什么；无租户空态混写“暂无数据或请求失败”。
- 运行列表只显示定义 ID，无耗时；已结束运行“当前节点”恒为 END。

用户在方向稿 A“时刻表（浅色优先）”与 B“夜班（深色优先）”之间选择 **A**。两种主题都保留，跟随现有主题偏好（系统 / 浅 / 深）。

## 设计原则

- **主视觉只有一处**：首页“业务日时刻轨道”把当天作业实例按开始到结束画在 00:00–24:00 横轴上，按 Worker 组分道，标出当前时间。这是本产品特有的画面，其余区域保持安静。
- **先回答“该处理什么”**：首页以按影响排序的“需要你处理”清单代替等权指标卡；全为 0 时只显示一条正常状态，不铺满零值卡。
- **颜色只表达状态**：成功、失败、运行中、警告、空闲五种语义色；类型、队列等分类信息使用中性标签，不再按颜色区分。状态始终有文字，不只靠颜色。
- **一种字体**：Barlow（拉丁与数字，等宽数字），中文回落系统字体；等宽字体只用于 ID、编码和链路标识。

## 范围与分期

第一期（本分支）：

1. `src/styles/tokens-handoff.css` 色板、字号与字体；Element Plus 派生色映射。
2. 布局外壳：侧边栏墨蓝底与选中指示、顶部栏层次。
3. 共享组件：状态标签改圆点胶囊、表格表头与行密度、页头标题层级。
4. 首页：业务日时刻轨道（作业实例按业务日查询，前端分页拉取并设上限，超出时明示截断）与“需要你处理”清单（复用现有 summary 指标）。
5. 工作流运行列表：以定义缓存显示工作流名称与编码，新增耗时列。

数据边界：时刻轨道只使用现有 `job-instances` 查询（`bizDate`、`startedAt`、`finishedAt`、`workerGroup`、`instanceStatus`），不推断截止时间；业务日截止与计划运行需后端提供可信数据后再加。工作流运行响应无触发方式字段，列表暂不显示。

后续期：其余页面按共享组件自然跟随后逐页复核；导航分组调整涉及路由与菜单契约，另行评估，不在本期改动。

## 第二期整改计划（2026-11-03，已确认）

状态：2026-11-03 用户确认本计划并要求开始批次 1；批次 0 已完成（PR #361 于 2026-11-04 合入 `main`，合并提交 `973c81af3`），批次 1 从 `main` 新建分支交付。问题清单以[前端界面与菜单调整台账](../backlog/frontend-ui-acceptance-2026-11-02.md#2026-11-03-用户反馈登记时刻表重设计分支)为准，本节只定目标、方案、顺序和验收，不重复列问题。

### 目标

1. 不再出现“点了没反应”：所有入口要么能用，要么明确告诉用户为什么不能用。
2. 表单与详情有一套共享外观和交互，新增、编辑、查看在全站长得一样、用法一样。
3. 减少重复的编辑入口：同一个对象只在一个地方编辑。
4. 再按台账逐页美化，并且每页改动都能追到共享规范，而不是各页自写样式。

### 现状事实（只读盘点）

- 无租户守卫：29 个页面文件在无租户时直接返回；18 个文件各自实现“打开新增”。实测无租户时通知与投递（已修）、文件渠道、文件模板、发布管理点击新增毫无反应。
- 表单：99 个文件含 `el-form`，抽屉 54 处、对话框 31 处；标签上置 57 处，左置用 6 种宽度。共享层只有只读的 `DetailDrawer`（14 个页面使用），没有编辑用的抽屉壳；分节、说明文字、校验提示和底部按钮各页自写。
- 第一期已完成共享 token、侧栏、状态标签、表格字号；表单和抽屉内部尚未纳入。

### 方案

**A. 入口可用性（缺陷，先做）**

- 新增共享组合式函数（暂名 `useTenantRequiredAction`）：入参为动作本身，无租户时提示“请先在顶部选择租户”，有租户才执行。页面的新增、导入、触发类按钮统一经它调用，替代各处静默 `return`。
- 对“当前不可用”的按钮（如标签管理的新增）统一为禁用加原因提示，不允许无说明的禁用。
- 用一条浏览器扫描用例固化：无租户时遍历带新增按钮的菜单页，断言每个按钮要么打开表单、要么跳转、要么给出提示。扫描需在可见页面运行，后台标签页的路由过渡不会完成。

**B. 共享表单体系（影响面最大）**

- 新增编辑抽屉壳（暂名 `FormDrawer`）：固定标题区（对象名与新增/编辑状态）、可滚动正文、底部固定操作区（次操作在前、主操作在后、提交 loading 与防重复提交）、未保存离开确认，三档宽度（窄/中/宽）。复用现有交互约定和抽屉 footer 规范。
- 新增表单分节组件（暂名 `FormSection`）：标题、一句说明、字段区；长说明折叠为次级文字。维护设置页的三节布局作为样板。
- 统一标签布局：抽屉和页面表单一律上置标签；仅高密度只读详情允许左置，宽度收敛到一个 token。
- 详情查看统一用 `DetailDrawer` 加分组键值区；原始 JSON 放到最后并可折叠。
- 规范写入 `docs/engineering/ui-interaction-conventions.md` 的表单章节，并在 `frontend-ui-ia-review` 检查表补对应条目。

**C. 编辑入口收敛**

- 先盘点：按业务对象（作业、工作流、文件渠道、模板、通知渠道/规则/Webhook、日历、窗口、队列、配额、参数、租户、账户等）列出每个对象的新增、编辑、查看入口位置，形成矩阵记录在本节附表。
- 收敛原则：一个对象一个编辑入口；列表行操作打开同一个编辑抽屉；详情页只读，编辑跳回同一抽屉；能就地切换的开关类字段在列表行内完成，不另开表单。
- 合并会改变交互和权限可见性，逐对象确认后再改，不批量替换。

**D. 页面美化（按台账）**

- 依赖 B 完成后进行，避免先美化再返工。顺序：权限自查、路由模拟、配置同步、流水线观测（含详情面板截断缺陷）、租户配置包、批次日回放、原子任务类型；再进入本方案“后续期候选页面”的 P1 页面（工作流图、作业定义、作业运行与详情）。
- 每页先截图记录现状问题，再按共享组件改造，前后对比截图写回台账。
