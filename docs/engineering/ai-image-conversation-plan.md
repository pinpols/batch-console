# AI 图片对话与回答复制实施方案

状态：待实施。本文定义目标契约和验收边界，不代表图片能力已经上线。`design/` 是只读设计稿目录，不在本方案中修改。

## 目标与范围

- 桌面完整页和全局助手共用一套输入体验：选择文件、拖入图片、从剪贴板粘贴截图（`Ctrl/Cmd+V`），发送前预览与移除；移动端支持系统相册/文件选择、预览与移除，粘贴仅在浏览器提供图片剪贴板数据时启用。
- 用户消息显示图片缩略图，点击在受控预览层查看原图；刷新后可从服务端历史恢复。会话删除和保留期到期后，图片不可再访问。
- 助手完整回答一键复制；代码块继续独立复制。复制的是实际回答 Markdown 文本（含正文中的来源标记），不是渲染后的 HTML、调试信息或会话元数据。
- 沿用现有 SSE 的 `started`、`delta`、`completed`、`failed` 和取消语义，不恢复旧 JSON 聊天接口。不做图片生成、OCR 专用服务、PDF/视频/音频、多轮图片编辑或把模型生成的远程图片嵌入回答。

## 已核实基线

| 当前能力 | 代码入口 | 图片改造影响 |
| --- | --- | --- |
| SSE 文本对话与取消 | `src/api/aiStream.ts`、后端 `ConsoleAiController` | 保持流式事件不变，扩展请求中的附件 ID |
| 文本附件 | `src/components/common/AiTextAttachmentPicker.vue`、`src/utils/aiTextAttachment.ts` | 目前读入浏览器并拼进 prompt；图片不可沿用此方案 |
| 会话持久化与历史 | 后端 `ConsoleAiConversationService`、`console_ai_turn` | 仅存加密文本；需增加图片元数据与受控读取 |
| 模型调用 | 后端 `DefaultConsoleAiApplicationService.callProvider` | 当前 `.user(promptPayload)` 为纯文本；需要真实多模态请求 |
| 对象存储 | 后端 `BatchObjectStore` | 已有 S3/文件系统抽象，但 AI 附件的授权和生命周期需独立实现 |
| 复制 | `src/components/common/AiMessageContent.vue` | 已支持代码块复制；缺少整条回答复制 |

后端会话持久化默认关闭，启用时有保留期限并禁止安全旁路。**图片能力要求会话持久化已启用**；未启用或处于安全旁路模式时，服务端拒绝图片上传和发送，前端不显示图片入口。这样图片发送与历史恢复始终是同一份承诺，不提供刷新后丢图的临时模式。

## 先行门槛：视觉供应商验证

1. 在现有 Spring AI `2.0.1` 与部署中实际配置的 OpenAI-compatible/Anthropic 模型上，做文本+图片**流式**调用探针，核实模型确实读取图片、可取消、返回用量且费用可以结算。探针使用无敏感数据的测试截图，不把密钥或原图写入仓库、日志和测试快照。
2. 按实际 `provider + model` 配置显式声明 `imageInput` 能力，不能仅因接口兼容 OpenAI 就推断支持视觉。当前 Spring AI 模型对照表仍把 DeepSeek OpenAI-proxy 标为纯文本，而 DeepSeek 官方视觉文档已声明 `deepseek-flash` 可接收图片；两者不一致，必须通过当前依赖和实际供应商的端到端探针确认。[Spring AI 2.0.1 模型对照](https://docs.spring.io/spring-ai/reference/api/chat/comparison.html)、[DeepSeek 视觉接口](https://api-docs.deepseek.com/guides/vision/)
3. 多模态请求只送到验证通过的模型。主模型不支持图片时，图片入口禁用并说明原因；若允许切换到已批准的视觉模型，需明确展示目标模型与成本。已发送部分 `delta` 后不切换供应商或重试；失败不能悄悄退化为“只看文字”的回答。
4. 图片 token/费用计入现有租户预算和审计。供应商未返回可计量用量时按保守预留结算或拒绝图片请求；先在受控环境校准供应商账单，不把文本字符预算当成图片成本上限。DeepSeek 官方说明图片按尺寸转换为 token 计费。[DeepSeek 视觉用量](https://api-docs.deepseek.com/guides/vision/)

## 交互规范

### 输入与发送

- 选择文件按钮使用现有图标体系；编辑区支持文件拖放与截图粘贴。文本粘贴仍进入文本框；剪贴板同时含文本和图片时优先图片，但不吞掉用户主动粘贴的普通文本。未聚焦聊天编辑器或其容器时不全局截获 `paste`。
- 待发送图片按加入顺序显示稳定尺寸缩略图、名称/大小、删除按钮和上传状态。图片未上传成功不可发送；发送中禁止改动本轮附件，但新输入草稿不得被上一轮完成事件清空。切会话、切租户、登出时撤销预览 URL 并清理本地状态。
- 点击发送只允许已通过校验且属于当前用户的附件 ID。服务端一次性绑定到新轮次；网络重试使用既有幂等键，不产生重复轮次或重复附件关联。仅图片无文字时允许发送，但服务端填入清晰的默认问题文案须先经产品确认；首版建议要求至少一个非空文字问题，避免无意上传。
- 全局助手和完整页使用同一附件状态与预览组件。桌面键盘焦点、移动端安全区、软键盘和窄屏预览均需人工验收；不改变现有页面布局密度。

### 消息、历史与复制

- 用户消息的图片展示与发送时的文本同属一个轮次；历史分页返回附件元数据和稳定 ID，不返回 base64、公网 URL 或对象存储 key。缩略图/原图请求走认证下载端点，权限校验后以私有响应返回；浏览器端不得长期缓存敏感图片。
- 暂停或失败的轮次在历史中显示真实状态；已绑定图片不因模型失败而变成孤儿。用户可重试问题，但不应隐式再次向供应商发送旧图片；重试须明确复用已保存图片或重新选择。
- 助手回答完成后提供始终可通过键盘访问的“复制回答”按钮，桌面可在悬停/聚焦时突出，移动端保持可发现。流式生成中按钮禁用或明确标为“复制当前内容”，首版建议等 `completed` 后启用。拒答只复制实际显示的拒答文字，不把隐藏错误码拼入剪贴板。
- 复制优先 `navigator.clipboard.writeText`；成功/失败均有非阻断提示。没有剪贴板权限时提示手动选择，不假报成功。代码块复制维持当前行为。复制操作不上传内容，也不额外写遥测原文。

## 后端契约与数据

**先改后端 OpenAPI，再生成前端类型**；以下是待评审的契约草案，不是已存在端点。

| 契约 | 预期行为 |
| --- | --- |
| `POST /api/console/ai/attachments` | 已认证的 multipart 上传；CSRF、租户/用户、频率、字节与像素限制；返回不透明 `attachmentId`、可展示元数据、草稿过期时间 |
| `POST /api/console/ai/chat/stream` | `AiChatRequest` 增加可选 `attachmentIds: string[]`；旧纯文本请求仍有效；服务端验证附件归属、状态、当前会话及模型能力后原子绑定轮次 |
| 历史轮次响应 | 增加有序图片元数据（ID、类型、尺寸、大小、展示名），不含对象 key/供应商文件 ID/公网 URL |
| `GET /api/console/ai/attachments/{id}/content` | 当前会话所有者经租户校验后读取；草稿仅上传者可读；禁缓存、限制 Content-Type，支持缩略图/原图的明确变体 |
| `DELETE /api/console/ai/attachments/{id}` | 仅允许上传者删除未绑定草稿；已绑定图片随会话删除或保留期清理，避免改写历史 |
| `GET /api/console/ai/capabilities` 或现有能力响应扩展 | 返回 `imageInput`、可用模型、上限及持久化状态；以服务端为准，不由前端硬编码推断 |

建议新增 `console_ai_attachment` 元数据表：`tenant_id`、不透明 ID、`owner_user_id`、可空的 `conversation_id/turn_no`、对象 key、归一化 MIME、字节数、宽高、哈希、状态、创建/过期时间。外键、索引和 RLS 沿用 `console_ai_conversation`/`console_ai_turn` 的租户边界。**数据库事务与对象存储写入不是一个原子事务**：先写受限草稿，绑定成功后转为已使用；失败/超时由定时清理补偿。删除会话先撤销读取权限，再异步幂等删除对象；过期任务分页处理并可重试，指标监测残留对象。对象 key 不从用户文件名拼接。

图片不得长期依赖供应商 `file_id` 或外部 URL：供应商侧生命周期与平台会话删除不同步。服务端从私有 `BatchObjectStore` 取受控副本，按经探针确认的 provider 格式组装 user 消息；多轮上下文是否重送历史图片必须设定显式上限和费用预算，首版默认**仅本轮发送图片**，历史图片用于回看而不自动重送模型。用户请求再次分析旧图时显式选择该图。

## 安全、限制与生命周期

- 建议首版 JPEG/PNG/WebP，单张不超过 5 MiB、最多 4 张、总计不超过 12 MiB、最长边不超过 4096 像素。服务端根据真实文件签名解码，限制解码后的像素/内存，重新编码并剥除 EXIF/GPS；拒绝 SVG、动图 GIF、损坏文件和伪造 MIME。具体阈值在浏览器与真实 provider 压测后定稿，不等于供应商官方上限。[OWASP 文件上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)
- 仅使用私有、已启用平台认可加密的对象存储配置；不把对象内容写入数据库、审计预览、异常日志、Sentry、前端本地存储或公共 CDN。上传与读取都执行认证、RBAC、租户和所有者校验；对象存储预签名直传若绕过加密装饰层则禁止。
- 草稿 TTL 建议 24 小时内；已绑定图片过期时间不晚于所属会话。会话删除、过期、用户权限变化、租户切换均不得再读取。后端审计记录附件 ID、哈希、大小、模型/决策和费用，不记录图片字节或可复原 URL。
- 图像中的文字是**不可信用户输入**，不能升级为 system/developer 指令；现有领域、工具授权和只读边界仍然生效。对含敏感截图显示“将发送给组织配置的模型”提示；是否允许外部供应商、哪些租户可用由部署策略控制。
- 本机和容器的图片上传体积限制需同时核对 Nginx、Spring multipart 与服务端硬限制；统一返回可本地化的错误码（格式、大小、像素、数量、归属、过期、模型不支持、预算不足），不在日志中输出原文件名或内容。

## 实施顺序与交付

1. **视觉探针与决策**：确认实际模型+Spring AI 路径的图片流式能力、usage、取消和成本，并决定是否允许切换到已批准的视觉供应商。探针不通过时不开放入口；会话持久化关闭时始终禁用图片。
2. **后端附件底座**：Flyway、RLS、私有对象存储、上传/读取/草稿删除、TTL 和补偿清理；单测与集成测试覆盖安全边界。同步 OpenAPI、协议文档和部署配置。
3. **后端多模态发送**：在既有流式聊天中校验并绑定附件，按能力发送图片，保留拒答、预算、审计、失败和取消语义；真实 provider 联测后再更新能力响应。
4. **前端双入口**：重新生成 `api.generated.ts`；复用图片输入、缩略图、历史预览、错误状态、完整回答复制组件；补齐中英文 i18n 和无障碍操作。
5. **验收与灰度**：先给测试租户/角色开放；核对真实供应商费用与删除残留，观察上传失败率、图片请求数和存储占用，再逐步放开。开关关闭时保留历史读取/删除权限，禁止新上传和发送。

粗估单人全职 **8–15 个工作日**，以视觉探针通过、既有对象存储加密配置可复用为前提；若需要自建 provider 适配层或改造存储加密、病毒扫描基础设施，应重新估期。

## 验收矩阵

- **接口**：纯文本请求不回归；图片流式回复可完成和取消；未知/过期/跨用户/跨租户附件均拒绝且 provider 调用次数为 0；幂等重试不重复绑定；图片用量进入租户预算。
- **存储**：伪造扩展名/MIME、超大文件、像素炸弹、损坏图片、重复删除、对象存储写入失败、数据库提交失败均有确定结果；草稿、会话删除和过期清理无可读残留。
- **历史**：上传、发送、刷新、分页、换会话、切租户、登出、过期和删除后的图片访问与 UI 一致；失败轮次不会产生可由他人访问的孤儿图片。
- **前端**：桌面文件选择、拖放、截图粘贴、普通文本粘贴、预览/移除、重复粘贴、上传失败、上传中发送限制、完整回答复制、代码块复制、剪贴板拒绝、键盘焦点和窄屏布局。依仓库现行规则，移动端独有交互做人工真机验收，独立业务逻辑才补单测。
- **验证层级**：Vitest 测状态/校验/复制，Playwright Desktop Chrome 测浏览器交互，后端 Testcontainers 测 DB/RLS/对象存储生命周期，真实后端+批准模型测试图片理解、SSE、取消、历史与费用。mock 成功不等于真实视觉能力通过。

交付门禁按两仓各自规则执行；后端 OpenAPI 为权威，前端 `npm run gen:api` / `gen:api:check`、`npm run build` 和必要的真实联测在各自 PR 中报告。`design/` 保持只读。
