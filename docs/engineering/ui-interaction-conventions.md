# 控制台交互约定

本文是桌面控制台筛选、状态展示、列表操作、日历、图表与全局提示的长期交互规范。新页面和现有页面改造优先遵循本文及 `docs/engineering/design-tokens.md`；如业务确有不同交互，应在页面或模块文档中说明原因，避免同类页面无意分叉。

## 筛选与查询提交

按用户是否已经提供完整条件、查询成本和组合条件数量决定查询时机，不以控件类型单独决定。

| 条件 | 默认交互 | 说明 |
| --- | --- | --- |
| 少量、互斥、语义清晰的状态/严重级别分段 | 选择后立即查询 | 适用于常见状态快捷切换；状态分段不能只换视觉而不更新结果。 |
| 完整的快捷时间范围（如最近 7 天）或单个业务日/日历 | 选择后立即查询 | 选项必须一次形成完整有效条件。 |
| 自由文本、ID、Trace、关键词 | 显式搜索；Enter 可提交 | 避免逐字符请求；远程建议使用防抖，选择后才查询。 |
| 可逐步编辑的起止日期范围 | 完成范围后查询，或点击搜索提交 | 不得在用户只选了起点、范围尚未完成时发起查询。 |
| 多选、多个组合字段、成本较高或可能返回大量数据的条件 | 点击搜索统一提交 | 让用户先完成条件，再发出可预期的一次查询。 |
| 单一布尔条件 | 仅当查询轻量且没有未提交草稿时可立即查询 | 否则与其他条件一起由搜索按钮提交。 |

### 混合即时与手动查询

- 同一工具栏混用即时查询和手动提交时，必须区分“当前已生效条件”与“尚未提交条件”。即时控件不得意外提交其他字段的草稿值。
- 如果无法清楚表达已生效/待提交状态，统一改为点击“搜索”后提交全部条件，避免表面上即时、实际又需要二次搜索的混合行为。
- 搜索应重置到第一页并同步可分享的 URL 条件；重置应恢复页面定义的默认条件并只触发一次加载。
- 加载中应防止重复提交；轮询/实时刷新不应清空用户筛选。

## 状态分段筛选

- 只用于少量、互斥、常用状态；状态数量多、过渡态多或技术枚举较多时，保留下拉或移入高级筛选。不要为了统一外观把所有枚举都铺成分段。
- “全部”是无筛选基线，固定放在选项最左侧；其后按业务流程或严重程度排列，不能按接口返回顺序漂移。
- 各状态使用一致的语义色：成功/正常为正向色，失败/停用等负向状态为危险色，运行/处理中为信息或强调色，待处理/警告为警示色；“全部”使用中性样式。选中态需要明显但克制，未选中状态仍可辨认。
- 颜色不可作为唯一编码。保留可读文字；计数只有在定义稳定、口径明确时才展示，缺失数据不能伪造为有意义的计数。
- 复用 `src/components/table/StatusSegment.vue` 及其语义 tone；不要在页面中另写一套仅靠颜色区分的分段按钮。

## 列表行操作

- 常用且安全的动作使用紧凑的小号按钮，优先图标加文字，让动作含义一眼可辨；纯图标仅用于高密度且含义明确的场景，并提供 tooltip、可访问名称和键盘焦点。
- 低频动作及每行操作过多时收进“更多”菜单，避免操作列过宽。具体折叠阈值由 `RowActions` 的共享实现负责，不在页面自行复制规则。
- 危险动作使用危险语义色和明确文字，执行前确认；不要仅凭红色或图标传达风险。可逆的启用/停用应显示与当前状态相匹配的动作。
- 操作列保持按钮尺寸、顺序、间距与加载/禁用反馈一致；不可用动作应说明原因或按权限隐藏，不能留下无反馈的空操作。
- 优先复用 `src/components/common/RowActions.vue`、图标库和设计 token。

## 日历与日期视图

- 周视图和月视图统一以周一为一周起点，表头顺序、日期网格和国际化标签保持一致。
- 月历单元格高度应服务于日期事件摘要，而不是撑满屏幕；使用紧凑稳定的网格、清晰的当前日/选中日/非本月日期层级。没有事件时不保留巨大的空白格。
- 月份标题与上月/今天/下月导航应邻近且布局稳定；窄屏下允许收敛为紧凑按钮或横向滚动，但不能遮挡日期或溢出容器。
- 日期、月份、周起始日和按钮文案都必须走 i18n；避免硬编码英文月份、星期和按钮，切换语言后需同步更新已渲染日历及弹层。
- 业务日历筛选只有在选择值完整后才查询；范围选择需等到范围有效。日期计算应使用项目统一的日期工具与业务时区约定，不自行拼接本地时区字符串。

## 图表与数据空态

- 图表形式由问题和数据决定，不把所有分布都画成同一种环图。时间序列优先折线/柱状，类别比较使用条形/柱状，构成比例才使用堆叠或环图；指标卡仅表达单值，不替代趋势或分布。
- 有数值轴和时间轴语义的图表应显示可读的轴、刻度/网格、单位和图例。空数据时保留图表标题及必要的轴/图表框架，并在绘图区显示明确空态；不编造零值、日期或刻度来伪装真实数据。环图等无笛卡尔坐标轴的图表不强加横纵轴。
- 空、单点、全零、极端长类别名和大量类别均需有合理表现；避免只有孤立色块而无法判断数据含义。工具提示、图例和颜色语义应一致，颜色不作唯一信息通道。
- 多张图表应根据分析任务选择不同且合适的表达，不以“形式多样”为由牺牲可比较性或可读性。

## JSON 与结构化内容

- 面向阅读的 JSON 默认格式化为纵向缩进结构，保留语法高亮/等宽字体、合理换行和滚动；不要把长 JSON 压成单行并依赖 tooltip 查看。
- 提供复制原始 JSON 的明确入口；大对象可折叠/展开，并在窄容器中限制高度、允许内部滚动，避免撑坏表格或页面布局。
- 非法或缺失 JSON 应按状态显示原始文本或空态，不能静默改写成看似有效的数据。

## 全局提示与侧栏

- Toast、成功反馈等短暂提示应脱离页面正常布局流，不推动主体内容上下跳动；位置需避开顶栏、浮动入口和关键操作，并在窄屏与安全区内可见。持续性、需要用户决策的告警使用横幅或页面内提示，不用短暂 Toast 替代。
- 全局横幅应占用稳定且克制的布局空间，内容过长时合理换行/折叠；关闭入口与自动关闭倒计时对齐，不遮住导航、筛选或表格首行。不能为了不挤压页面而把可操作提示放到屏幕外或与其他控件重叠。
- 侧栏展开/收起控件在展开和折叠状态都应可发现、可操作，使用同一组方向语义一致的图标并提供 tooltip/可访问名称。折叠后仍可访问导航分组和底部状态区；窄宽度时图标不得裁切或错位。

## 国际化与响应式验收

- 所有新增用户可见文案、按钮、tooltip、图表轴/图例、日历标签、空态和状态名称都使用 `t()`；`zh-CN` 与 `en-US` 的键保持一致。
- 切换语言应更新当前页面的动态标题、格式化日期、下拉选项、图表和弹层，不只更新静态模板；异步数据的展示映射应依赖当前 locale，而不是在加载时缓存旧语言文案。
- 验收至少覆盖桌面常见宽度与窄屏、长文本、空/加载/错误/有数据状态，以及关键筛选、重置、分页和操作反馈。验证文档或组件存在不等于所有页面都已完成巡检。

## 共享实现入口

- 状态分段：`src/components/table/StatusSegment.vue`
- 行操作：`src/components/common/RowActions.vue`
- 列表筛选工具栏：`src/components/table/OpsFilterToolbar.vue`（若页面采用）
- 设计变量：`src/styles/tokens-handoff.css`，规则见 `docs/engineering/design-tokens.md`

如果共享组件的能力或实际目录发生变化，应先更新实现并同步修订本节引用，避免文档指向过期入口。

## 审查方法与证据

具体UI、交互与视觉的常见问题、反例和复核步骤由[UI审查Skill](../../.agents/skills/frontend-ui-ia-review/SKILL.md)及其[检查表](../../.agents/skills/frontend-ui-ia-review/references/common-ui-checks.md)维护。沿当前页面任务检查正常/加载/空/错/提交/权限、长数据、中英文/主题/窄屏和键盘场景，记录实际角色、视口、数据与构建身份。纯视觉建议、现行规范偏差、可用性问题和确认Bug分别陈述；历史截图或静态门禁不能证明当前页面已验收。
