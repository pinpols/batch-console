# Console AI 助手前端实施方案

- **状态**：双端全局入口、版本化页面上下文和服务端会话 UI 已接入；安全模式后端配本地模型桩已通过会话创建、刷新恢复和删除的浏览器 E2E。历史拒答决策和发送中草稿已补回归，390px 浏览器已验证移动抽屉焦点；外部 provider、来源引用、授权能力和真实软键盘仍待验收（2026-10-01）
- **范围**：`batch-console` 桌面与移动端交互、页面上下文、会话体验和前后端契约
- **后端总方案**：`file-batch-system` 仓库的 `docs/plans/ai-assistant-contextual-experience-and-cost-governance-2026-09-29.md`
- **现状核对日期**：2026-09-29

## 1. 目标与边界

让有权限的用户能从 Console 当前工作页面随时询问批量调度系统问题，同时保留现有完整 AI 助手页作为会话和审计入口。前端负责清晰、低干扰的交互和最小化上下文传递；认证、授权、租户隔离、领域拒绝、费用限制和数据读取均由后端执行。

前端不得：

- 把 AI 助手包装成通用问答入口，或自行决定领域授权结果。
- 抓取页面 DOM、表单、日志全文或任意 store 状态并发送给模型。
- 将用户输入、模型回答或敏感业务上下文写入 `localStorage`、遥测事件或普通前端日志。
- 仅凭隐藏按钮、路由守卫或前端传入的 `tenantId` / 权限字段作为安全控制。
- 在后端未实现会话持久化、取消或来源引用契约时，通过前端假状态宣称这些能力已生效。

## 2. 当前实现基线

- `/system/ai-chat` 保留聊天/审计双标签，已接服务端会话列表、历史分页、删除和成本摘要；本地后端默认关闭 AI 会话持久化，列表不可用时不声称对话已保存。隔离联测实例开启持久化并使用本地模型桩，已验证真实浏览器的创建、刷新恢复和删除。
- `src/composables/useAiChatSession.ts` 统一全页与侧栏发送状态；请求包含 `contextVersion=v1`，页面模式仅发送白名单 `pageType`，未发送后端尚未对具体对象重新授权的 ID。
- 历史恢复保留服务端 `promptDecision`（含预算拒绝）；发送请求期间用户继续编辑的问题草稿不会因前一响应成功而丢失。
- 发送错误根据后端限流、拒绝、服务不可用及请求超时状态显示不同提示；页面保留未成功提交的问题草稿供重试。当前浏览器限流回归使用路由模拟，不等同于真实配额耗尽验收。
- 桌面 `LayoutHeader` 与移动 `MobileAppBar` 已挂载全局入口；当前沿用 ADMIN 角色门槛。后端 `/auth/me` 尚未提供 `AI_ASSISTANT_USE` 能力，不能将入口可见性等同于最终服务端授权。
- 后端 `AiChatResponse` 尚无结构化来源引用和取消生成契约；前端不伪造引用、停止按钮或持久化成功状态。真实 provider、限流、预算和跨租户会话验收仍需受控环境。
- `src/types/api.generated.ts` 由后端 OpenAPI 生成，契约变化必须先更新后端 OpenAPI，再执行 `npm run gen:api`，禁止手改生成类型。

## 3. 目标交互

### 桌面端

- 在认证后的桌面应用布局挂载全局 AI launcher；入口位置不覆盖全局导航、页面主操作或通知控件。
- 点击后打开可收起的右侧面板；面板宽度有稳定上限，支持调整（若现有 Drawer 组件可满足则优先复用），主页面仍可辨识和操作。
- 提供明确的“询问当前页面”和“询问系统问题”模式。当前页面模式显示正在使用的页面/对象上下文，并允许用户移除上下文；系统问题模式不附加业务对象。
- 保留 `/system/ai-chat` 完整页作为会话历史与审计入口。浮层和完整页共用 API client、契约类型、消息呈现及错误映射，不复制聊天实现。

### 移动端

- 在认证后的移动布局提供一致入口；助手采用全屏面板或底部抽屉，输入区适配软键盘和安全区。
- 不依赖桌面路由在移动设备上的降级行为；全局入口由移动布局显式挂载。
- 返回/关闭后恢复原页面和滚动位置。窄屏下不并排展示长消息与审计表格。

### 回复呈现

- 展示拒绝原因、加载中、无证据、provider 错误、超时、限流、预算耗尽和会话失效等服务端明确状态；不把拒绝伪装成成功回答。
- 若 API 返回来源引用，提供可访问的来源标签和 Console 深链；显示实时数据的采集时间。没有来源时不虚构引用或确定性。
- Markdown 渲染须使用项目认可的安全渲染路径；代码块可复制，长内容可滚动，用户与助手消息有可读的角色标识。

## 4. 组件与状态边界

建议组件职责如下，实际命名按实现时现有组件规范确定：

| 职责 | 约束 |
|---|---|
| 全局入口 | 仅负责打开助手；依据服务端下发/前端权限 store 的 AI 能力显隐，不自行推导权限 |
| 助手面板 | 打开/关闭、模式切换、明确的页面上下文摘要和响应式布局 |
| 对话视图 | 消息序列、发送状态、拒绝/错误状态、来源引用与可访问焦点管理 |
| 会话状态 | 当前租户下的会话列表、当前会话和分页消息；切租户或登出立即清空内存并重新拉取 |
| 页面上下文适配器 | 按路由元数据/白名单提供页面类型和最小对象 ID；没有适配器时只允许系统问题模式 |
| API 模块 | 仅通过 `src/api/client.ts` 发请求，使用 OpenAPI 生成类型，不在组件内直接构造 HTTP 请求 |

用户输入和回答默认只保存在内存状态；服务端持久化会话可用后，由服务端作为恢复权威。避免使用 `localStorage` 缓存对话正文。若将来为草稿提供本地暂存，必须独立评审敏感信息、登出清理和租户切换行为。

## 5. 页面上下文与权限

- 上下文按页面白名单适配，首批只传 `pageType`、允许的业务对象类型/ID，以及必要的租户作用域提示；不传整段页面文本或任意 query/body。
- 业务对象 ID 从已解析路由参数或已加载实体的主键产生，不从可编辑文本框、URL 任意 query 参数或 DOM 抽取。
- 前端切换页面时，面板不应静默把旧对象上下文替换成新对象。应提示用户确认更新，或明确标记当前问题仍绑定旧对象；新会话默认采用当前页面上下文。
- 前端传入的 `tenantId` 仅用于现有 Console API 契约兼容。后端必须依据认证主体验证租户，不能信任请求字段。
- 未登录、AI 功能关闭或缺少能力时不渲染入口；深链进入 AI 页面仍由路由守卫处理，但 API 权限校验是最终边界。
- 页面上下文只读。回答中的重跑、审批、取消或改配置建议链接到现有受控页面，不提供 AI 直接写操作。

## 6. 后端契约依赖

全局会话体验实施前，后端至少需定义并通过 OpenAPI 暴露以下契约；字段名以最终后端 schema 为准：

1. 版本化聊天请求：可选页面类型、对象类型/ID；服务端从认证上下文解析租户和用户。
2. 会话列表、会话详情/分页消息、新建会话和删除会话（是否允许删除、软删或保留期遵循数据治理决策）。
3. 聊天响应中的消息 ID、会话 ID、明确的决策/拒绝状态、token/限流元数据，以及可选来源引用。
4. 过期会话、越权对象、租户不匹配、配额耗尽和 provider 故障的稳定错误码。
5. 若产品需要“停止生成”，定义服务端取消语义及请求关联 ID。仅 abort 浏览器请求不能宣称停止了模型执行或费用计量。

契约落地顺序：后端 DTO/授权/租户过滤与 OpenAPI → `npm run gen:api` → 前端 API client、错误类型、mock/fixture、页面及测试。无契约的内容先显示为不可用，不伪造端点或本地持久化行为。

## 7. 国际化、可访问性与隐私

- 所有用户可见字符串均进入 `src/locales/zh-CN.ts` 和 `src/locales/en-US.ts`，保持 key 一一对应；不得在聊天组件中硬编码文案。
- launcher 使用有名称的按钮语义和 tooltip；面板支持键盘打开、关闭、焦点进入与关闭后焦点恢复。Escape 关闭前不得丢弃未发送输入而不提示。
- 新消息可通过适当的 `aria-live` 状态播报，但不要在流式响应每个 token 上触发屏幕阅读器播报。
- 输入上限、剩余预算/限流状态如需呈现，应来自服务端契约；不得在客户端估算并宣称为权威费用。
- 页面明确告知对话内容是否会保存及可能发送到组织批准的模型服务。告知与后端实际保留和 provider 配置一致。

## 8. 分阶段实施

### Phase 0：契约与产品决策

- 与后端总方案对齐入口角色、页面上下文对象、会话保留/删除、来源引用和取消语义。
- 先生成并评审 API schema 与错误契约；核实现有 ADMIN 路由限制如何迁移到 AI 专用能力。

### Phase 1：全局入口与非持久化面板

- 实现桌面/移动布局入口和面板，复用现有聊天 API；支持系统问题与页面上下文的显式模式。
- 页面上下文采用白名单适配器；权限不足/AI 关闭时无入口，服务端拒绝仍可正确显示。
- 保留完整 AI 页面与审计功能，避免影响既有管理员工作流。

### Phase 2：服务端会话体验

- 后端会话 API 可用后，实现会话列表、历史恢复、分页、重命名（若后端支持）和删除。
- 处理切租户、登出、会话过期和并发发送；不在前端复制服务端历史为另一份持久化数据。

### Phase 3：来源与质量闭环

- 呈现知识文档和实时查询来源、时间、深链及证据不足状态。
- 依据试点反馈调整快捷问题和页面适配器；每新增一种上下文均配权限及跨租户反例测试。

## 9. 验收要求

- `npm run typecheck`、`npm run lint`、`npm run check:i18n`、`npm run check:docs` 通过；OpenAPI 变化时 `npm run gen:api:check` 通过。
- 单测覆盖页面上下文白名单、未知页面回退到无上下文模式、租户切换清理、API 错误映射和会话状态迁移。
- Playwright 覆盖桌面与移动入口、打开/关闭/键盘焦点、页面上下文确认、AI 拒绝、超时/限流、刷新恢复（仅在后端持久化 API 实施后）和权限拒绝。
- 视觉检查确认面板不遮挡高频主操作；移动软键盘出现时输入区可操作，文本无重叠或裁切。
- API mock 不能代替后端集成验收；跨租户、越权对象和伪造上下文必须与后端真实授权测试联动验证。

## 10. 风险和处置

| 风险 | 前端控制 | 必须由后端保证 |
|---|---|---|
| 错误页面上下文导致误诊 | 白名单适配器、显式上下文提示、页面切换确认 | 按当前权限重新读取对象并拒绝越权 |
| 租户切换后展示旧会话 | 清理内存状态并按新租户重取 | 会话查询同时校验 tenant 与 owner |
| 用户误以为对话仅本地保存 | 在 UI 说明保存和模型数据出口 | 实际保留、删除、审计与 provider 策略 |
| 浏览器取消被误认为停止模型 | 只有后端取消契约成功才显示已停止 | 取消执行、费用计量和状态收敛 |
| 模型输出造成 XSS | 使用受控 Markdown 安全渲染 | 输出不作为可信 HTML 或授权输入 |
| 角色权限前后不一致 | 能力驱动入口与路由显隐 | 每次 API 请求强制认证授权 |
