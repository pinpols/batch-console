# 前端约定与 CI 守卫周期复核

本文是人工/AI 复核入口，不替代 [AGENTS.md](../../AGENTS.md)、[测试体系](../testing/README.md)、[CI 手册](../runbook/ci.md)或后端 OpenAPI。CI 可检查确定性规则，但不能证明页面仍方便使用、权限和租户切换仍正确，或浏览器验收确实连接目标环境。

## 复核节奏

- **每月增量**：以两仓上次审查提交到当前 `main` 的差异为范围；配置维护、权限、认证、API、运行监控和运维动作优先。关键路径变更后立即复核，不等月度窗口。
- **每季度存量抽样**：选择一条跨页面/跨仓用户旅程、一个大页面、一个治理基线或例外、一个部署与验收流程；不得只审本月新增文件。
- **发布前/事故后**：从目标环境按角色操作，并复核回滚、错误态、数据结果与证据留存。模拟路由、编译和绿色 workflow 不替代目标环境验收。

| 主题 | CI 能守住的部分 | 仍需人工/AI 核对的退化 | 抽样方法 |
|---|---|---|---|
| 配对后端契约 | `gen:api:check`、类型检查、API 单测 | 同名分支缺失时回退后端 main；字段类型一致但权限、默认值、错误语义或实际页面反馈已漂移 | 记录后端 OpenAPI SHA、前端生成类型 SHA；从 Controller/DTO 到 API 客户端、页面、mock 和 E2E 追一条成功及失败路径 |
| 角色与租户 | 路由/类型/部分权限测试 | 页面隐藏不等于后端授权；切租户后缓存、轮询、分页和旧响应可能串上下文 | 用四类正式角色分别走列表→详情→操作；抽查租户标识、query key、请求头和拒绝后的 UI 状态 |
| 配置维护与运维闭环 | 表单校验、API 契约、部分 E2E | 配置包列数/默认值、平台资源暴露、审批与恢复动作不符合运维实际操作 | 按真实租户场景走建作业、导入/发布、运行、诊断、重试/补数；核对 Excel、文案、权限、后端结果和可恢复性 |
| UI、i18n 与可访问性 | 译文可编译、key 结构、ESLint、视觉基线和 axe 的既有用例 | 新页面仍可能出现硬编码文案、溢出、误导性空态、键盘断点；复杂度计数不等于易用性 | 桌面/移动各选关键页面与长字段、空/错/加载态，在中英文和四角色下检查密度、操作路径和键盘焦点 |
| 状态与异步数据 | 类型、单测、局部页面 E2E | 请求失败被空数组掩盖、过期响应覆盖新租户数据、轮询/取消/刷新状态失真 | 沿一次 API 失败、慢响应和租户切换追踪 store/query/组件；核对最后成功时间与错误提示 |
| 浏览器安全与部署 | `vue/no-v-html`、安全头、依赖/镜像扫描和环境变量登记 | SSRF/开放重定向、Cookie 域、CSP 与反向代理拓扑需结合实际部署；注册变量不代表生效 | 抽样登录/文件/外链路径和 staging 产物，核对真实 origin、Cookie、代理、响应头及版本 SHA |
| 测试代表性和 CI 自身 | Vitest、Playwright、静态治理、workflow 检查 | `test.skip`、同源断言、fixture 过时、报告性步骤和误配 URL 会给出错误的绿色印象 | 逐项核对输入文件→触发条件→执行命令→退出码→required check；抽一条应拦与一条应放行案例，记录 PASS/SKIP/FAIL |
| 文档与基线 | 链接、路径、关键词、SBOM 与预算检查 | 文档内容可能过时；可维护性/UI 复杂度基线可人为抬高；数字预算不能代表产品质量 | 核对权威代码、当前部署和真实操作；基线变化列新增项、owner、理由及删除条件，过时报告归档 |

## CI 守卫自审决策

1. **加入阻断门禁**：约束可机器判断、有稳定事实来源、可写应拦与应放行用例，误报成本可控。例如治理基线异常扩大、staging E2E 目标 origin 与预检不一致。
2. **保持报告或增量门禁**：规则有价值但存量债务或误报未收敛。记录 owner、范围、到期/删除条件；不能用扩大基线掩盖新问题。
3. **留给人工/AI 周期审查**：业务可用性、文案质量、抽象是否适度、文档与生产现状、目标环境灾备或容量证据。这些不是关键词/行数检查能裁决的。
4. **收窄或删除守卫**：等价配置仅因格式被拦，或者两个 job 在同一运行时重复执行、没有独立失效模式时，先用历史耗时和正反例证明收益，再改 workflow；不要为提速牺牲必需验收。

审查记录须写明两仓基线提交、范围、样本、证据层级、未执行项和整改归属。结论区分确认缺陷、待验证风险、设计决定与抽样未发现问题。2026-10-12 的前后端静态复核快照见配对后端 `docs/audit/cross-repo-governance-drift-review-2026-10-12.md`；其中的缺陷状态不随本文自动更新。
