# 前端可观测性方案

## 整体架构

前端可观测性分两层（`telemetry.ts` 已并入 `logger.ts`，当前实现以代码为准）：

```
┌────────────────────────────────────────────────────────────────┐
│  前端(Vue)                                                       │
│                                                                  │
│  ┌─────────────────────────────┐  ┌───────────────────┐         │
│  │ logger.ts (统一埋点 + 日志)    │  │ Sentry 错误监控    │         │
│  │ localStorage 环形 buffer       │  │ sentry.ts          │         │
│  │ → 后端 REST → 结构化应用日志  │  │ → Sentry Server    │         │
│  └────────────┬─────────────────┘  └─────────┬─────────┘         │
└───────────────┼──────────────────────────────┼───────────────────┘
                ↓                              ↓
   /api/console/telemetry/events    Sentry / GlitchTip
                ↓
       stdout / OTLP / Loki（由部署环境决定）
```

| 层级 | 定位 | 存储 | 实现 |
|------|------|------|------|
| 前端日志 + 埋点 | 本地排障兜底；可选发送到后端日志管道 | localStorage + 结构化应用日志 | `src/utils/logger.ts` |
| Sentry 错误监控 | JS 异常、白屏、性能追踪 | Sentry Server | `src/utils/sentry.ts` |

---

## 一、本地操作日志（logger）

离线可用的环形缓冲区日志，不依赖后端，用于用户侧排障。

### 核心文件

`src/utils/logger.ts`

### 存储

- **运行时**：模块级变量 `buffer: LogEntry[]`，环形缓冲区，上限 500 条
- **持久化**：`localStorage`，key 为 `batch-console-oplog`

```json
{
  "seq": 42,
  "entries": [
    {
      "id": 1,
      "ts": "2026-04-10T08:00:00.000Z",
      "type": "route",
      "level": "info",
      "name": "页面切换：首页",
      "page": "/ops/summary",
      "props": { "from": "/login" }
    }
  ]
}
```

- 每 10 秒落盘一次 + 页面关闭前落盘
- localStorage 写满时自动缩容到 200 条；数据损坏时静默重置

### 日志分类

| 类别 | 级别 | 采集位置 | 说明 |
|------|------|----------|------|
| `route` | info | `src/router/index.ts` afterEach | 路由切换 |
| `click` | info | `v-track-click` 指令 | 按钮/操作点击 |
| `api` | info / error | `src/api/interceptors.ts` | API 请求结果 |
| `error` | error | `src/main.ts` 全局错误处理 | Vue 异常、window.error、unhandledrejection |

### 查询与导出

```ts
import { queryLogs, exportLogsAsJson, clearLogs } from '@/utils/logger'

queryLogs({ type: 'error', keyword: '/api/job', since: '2026-04-10' })
const json = exportLogsAsJson()  // 导出 JSON 供排障下载
clearLogs()                       // 清空本地日志
```

### 数据结构

```ts
type LogType = 'route' | 'click' | 'api' | 'error'
type LogLevel = 'info' | 'warn' | 'error'

interface LogEntry {
  id: number
  ts: string
  type: LogType
  level: LogLevel
  name: string
  page: string
  props?: Record<string, unknown>
}
```

## 二、行为埋点 SDK（telemetry）

批量上报用户行为到后端，用于功能使用率分析、访问统计。

### 核心文件

`src/utils/logger.ts`(2026-05-15 起 telemetry 与 logger 合并)

### 设计

- **环形 buffer**:本地 500 条 + localStorage 兜底,刷新不丢
- **批量上报**:每 15 秒 POST `/api/console/telemetry/events`,单批 50 条
- **总开关**：默认关闭；构建时设置 `VITE_TELEMETRY_ENABLED=true`，或运行期设置 `localStorage['batch-console-telemetry']='on'` 临时打开排障
- **页面关闭**：`visibilitychange` + `beforeunload` 使用 `fetch(..., { keepalive: true })` 尝试发送，不保证浏览器卸载期间必达
- **失败处理**：成功后推进游标；4xx 丢弃当前批次；5xx/网络失败保留游标并在下一轮重试，始终不影响业务操作
- **持久化边界**：前端只保留最多 500 条本地记录；后端接收后写结构化应用日志，不写独立 telemetry 数据库表

### 上报端点

`POST /api/console/telemetry/events`

### Payload 格式

```json
{
  "app": "batch-console",
  "sessionId": "1712736000000-a1b2c3",
  "events": [
    {
      "type": "route",
      "name": "首页",
      "ts": "2026-04-10T08:00:00.000Z",
      "page": "/ops/summary",
      "props": { "from": "/login" }
    },
    {
      "type": "click",
      "name": "触发 Job",
      "ts": "2026-04-10T08:00:05.000Z",
      "page": "/job/list",
      "props": { "jobId": 123 }
    }
  ]
}
```

### 事件类型

| type | 采集点 | 说明 |
|------|--------|------|
| `route` | router afterEach | 页面访问 |
| `click` | v-track-click 指令 | 按钮/操作点击 |
| `api` | interceptors 成功响应 | API 调用（含耗时） |
| `error` | interceptors 错误响应或全局异常 | API 错误、Vue/window/Promise 异常 |

### 手动调用

```ts
import { logRoute, logClick, logApi, logError } from '@/utils/logger'

logRoute('页面切换：首页', { path: '/ops/summary' })
logClick('触发 Job', { jobId: 123 })
logApi('GET /api/jobs', 'info', { status: 200, durationMs: 120 })
logError('导出报表失败', { format: 'xlsx' })
```

### 环境变量

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `VITE_TELEMETRY_ENDPOINT` | 上报端点 | `/api/console/telemetry/events` |
| `VITE_TELEMETRY_ENABLED` | 是否启用 | `false` |

## 三、Sentry 错误监控

专业错误监控，自动采集 JS 异常、性能数据，支持 Source Map 还原。

### 核心文件

`src/utils/sentry.ts`

### 特点

- **按需加载**：DSN 为空时不加载 SDK，零 bundle 开销（动态 import）
- **浏览器追踪**：集成 `browserTracingIntegration`，自动关联路由
- **噪音过滤**：忽略 ResizeObserver、chunk 加载失败等无意义异常
- **租户标签**：自动附加 `tenantId` tag，便于按租户筛选
- **采样率**：生产 0.2，开发 1.0

### 环境变量

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `VITE_SENTRY_DSN` | Sentry DSN 地址 | 空（不启用） |

### 部署步骤

1. 安装依赖：`npm install @sentry/vue`
2. 在 `.env.production` 中填入 `VITE_SENTRY_DSN=https://xxx@sentry.example.com/1`
3. CI 中上传 Source Map：`sentry-cli sourcemaps upload dist/`

## 四、采集点一览

所有埋点统一进入 `logger.ts`：启用时写入本地日志，并按批次上报后端结构化日志；关闭时不写入、不启动定时器。

| 采集点 | 文件 | 本地日志 | Telemetry | Sentry |
|--------|------|----------|-----------|--------|
| 路由切换 | `src/router/index.ts` | `logRoute` | `/api/console/telemetry/events` | 自动（Sentry 开启时） |
| 按钮点击 | `src/directives/trackClick.ts` | `logClick` | `/api/console/telemetry/events` | - |
| API 成功 | `src/api/interceptors.ts` | `logApi(info)` | `/api/console/telemetry/events` | - |
| API 失败 | `src/api/interceptors.ts` | `logApi(error)` | `/api/console/telemetry/events` | - |
| Vue/window/Promise 异常 | `src/main.ts` | `logError` | `/api/console/telemetry/events` | 自动（Sentry 开启时） |

## 五、点击埋点用法

使用 `v-track-click` 指令（同时写入本地日志 + telemetry 上报）：

```vue
<!-- 字符串形式 -->
<el-button v-track-click="'触发 Job'">触发</el-button>

<!-- 对象形式（携带附加数据） -->
<el-button v-track-click="{ action: '审批通过', id: row.id }">通过</el-button>
```

## 六、初始化

在 `src/main.ts` 中完成两类初始化：

```ts
initLogger()                         // 本地日志与可选埋点上报
initSentry({ app, router, dsn })      // 可选 Sentry 错误监控
```

## 七、后端对接

后端已适配前端 Payload 格式（见 OpenAPI `receiveTelemetryEvents`），字段完全一致。

```
POST /api/console/telemetry/events
Content-Type: application/json
Body: TelemetryPayload（见上方 Payload 格式）
```

处理流程：console-api 接收 → 通过 SLF4J/MDC 写结构化应用日志 → 由部署环境配置的 stdout/OTLP/Loki 管道处理。当前没有 Kafka topic、独立 telemetry 表或前端埋点查询页面。

> 前端埋点用于排障和可选的行为观测，不等同于控制台操作审计。需要证明谁在什么时候对哪个租户执行了什么写操作时，应查询 `console_operation_audit`（`/api/console/queries/operation-audits`）；该记录由后端 `@AuditAction` 切面产生，不依赖前端点击埋点。

### 推荐 Grafana 看板维度

- 后端日志平台可按 `frontendPage`、`frontendEventType`、事件名称统计页面访问、点击和错误
- 按 `type=error` 与 `props.status` 统计接口错误率（前提是日志管道保留对应结构化字段）
- 租户维度使用请求上下文和日志 MDC；不要把密码、token、Secret 或完整请求体放入 `props`
