# Console 使用率统计前端方案

状态：前端只读页面与真实本地 API/PG 只读对账已验证；当前后端日聚合只包含操作审计投影，未完成作业/文件终态对账与指标目录冻结（2026-10-01）

后端总体方案见：`../file-batch-system/docs/plans/console-usage-statistics-plan-2026-09-29.md`。

## 1. 前端职责

前端只负责提供两类信息：

1. 页面访问和前端错误等诊断遥测；
2. 无法由后端业务结果表达的页面使用趋势。

前端点击不能作为业务成功依据。配置导入、Job 触发、重跑、补偿、导出等功能的使用率，以后端成功操作和业务终态为准。

## 2. 现有 logger 行为

`src/utils/logger.ts` 是唯一入口：

- `route`：路由进入；
- `click`：按钮、菜单和显式操作点击；
- `api`：API 成功响应；
- `error`：API 错误、Vue 异常、window 异常和未处理 Promise 异常；
- 最多保留 500 条本地记录，key 为 `batch-console-oplog`；
- 启用后每 15 秒批量 POST `/api/console/telemetry/events`，每批最多 50 条；
- `VITE_TELEMETRY_ENABLED` 默认 `false`，运行期可用 `batch-console-telemetry=on` 临时排障；
- 上报失败不阻塞页面操作，也不保证统计数据完整。

前端遥测的落点是后端结构化应用日志，不是 `console_operation_audit`，也不是独立统计表。

## 3. 事件使用规则

### 3.1 页面访问

页面访问使用稳定路由或页面编码，不使用本地化标题作为统计维度：

```text
ui.page.ops-summary.view
ui.page.job-instances.view
ui.page.config-management.view
```

中文、英文、租户自定义文案变化不能改变页面编码。

### 3.2 点击事件

点击事件只用于诊断和入口趋势：

- 仅给需要定位问题或评估入口曝光的控件添加 `v-track-click`；
- 不给每一个普通按钮机械添加埋点；
- `props` 只能携带业务无关或已脱敏的短字段；
- 禁止写入密码、Token、Secret、完整表单、文件内容和完整响应体；
- 重要业务操作必须等待后端响应，并以 operation audit / 业务结果作为成功统计。

### 3.3 后端业务指标

前端不自行统计以下成功率：

- 导入是否成功；
- 导出文件是否完整；
- 重跑是否创建成功；
- 补偿是否完成；
- Worker 任务是否进入 SUCCESS。

这些指标由后端转换为 `metric_code`，前端只负责展示查询结果。

## 4. 前端查询页面

P2 阶段新增“使用率”只读页面，建议放在“观测”分组，不放到配置或作业操作分组。

建议路由：

```text
/observability/usage
```

建议视图：

- 指标卡：成功操作数、失败操作数、活跃页面数；
- 趋势表：按日期和指标展示 `eventCount / successCount / failureCount`；
- 功能排行：按 `metricCode` 聚合；
- 页面排行：只展示 route 维度；
- 筛选：租户、日期范围、指标、页面、应用版本。

页面必须标注：

> 统计数据来自后端日聚合，前端埋点为 best-effort，不用于计费、对账或合规取证。

## 5. API 与类型同步

后端落地 `GET /api/console/queries/usage-summary` 后，前端必须同步：

1. 更新后端 OpenAPI；
2. 执行 `npm run gen:api`；
3. 在 `src/api` 增加 typed wrapper；
4. 使用生成类型实现查询参数和响应；
5. 增加空数据、跨租户拒绝、日期范围和分页测试；
6. 在菜单权限配置中只给审计员、管理员和租户管理员开放。

不允许为统计接口重新引入 `Map<string, unknown>` 响应，也不允许页面自行拼接后端字段。

## 6. 联测场景

| 场景 | 预期 |
|---|---|
| 点击导入后接口失败 | 只计前端诊断错误，不能增加导入成功数 |
| 点击导入后后端成功但页面刷新 | 成功数由后端结果统计，不依赖页面是否刷新 |
| 中英文切换后使用同一功能 | 使用同一个 `metricCode` |
| 租户 A 查询使用率 | 只能看到租户 A |
| telemetry 开关关闭 | 业务功能正常，页面不产生遥测请求 |
| 网络短暂中断 | 页面操作不阻塞，遥测允许丢失或延迟 |
| 版本升级后查询历史 | 历史指标编码保持兼容，版本作为筛选维度 |

### P0：现状收口

- 保持 `logger.ts` 为唯一埋点入口；
- 删除旧 `telemetry.ts`、旧事件类型和未实现消费链路文档；

### P1：契约联测

- 对齐 OpenAPI、生成类型、API wrapper 和测试 fixture；
- 验证 operation audit 与业务结果的成功/失败口径；
- 验证开关关闭、网络失败、重复批次和跨租户访问。

### P2：只读使用率页面

- 新增 `/observability/usage`；
- 与现有观测页面保持表格、筛选、空态和权限样式一致；
- 只读展示日聚合，不提供修改、重放或清理动作。

## 8. 不做的前端能力

- 不把普通点击日志展示成审计日志；
- 不在前端计算业务成功率；
- 不采集和展示原始用户行为轨迹；
- 不在前端引入新的埋点 SDK、Kafka 客户端或 ClickHouse 客户端；
- 不为了统计页面改变现有作业配置和运维流程。
