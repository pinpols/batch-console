状态：审查记录，只读。依据 `src/constants/navigation.ts`、`src/constants/pageMeta.ts`、`src/router/index.ts` 与相关页面源码，在 `fix/docs-static-redirect` 工作区核查；未做浏览器复核，未改代码。发现与建议不自动授权实施。

方法遵循 `frontend-ui-ia-review`。分母为导航登记的 7 组 56 个入口（28 个侧栏隐藏）、桌面路由重定向 13 条、移动端 11 个页面。已在[导航分组审查（2026-11-02）](../navigation-grouping-review-2026-11-02.md)和[任务走查（2026-11-05）](./task-walkthrough-2026-11-05.md)中处理的问题不重复登记。

## 发现

2026-11-06 已对照前后端源码核实全部待核实项，并新发现三处缺陷：用户菜单没有“我的账户”（修改密码）入口；自助服务“暂停触发器”对租户角色可见但接口仅平台管理员可用，提交必然 403；桌面补跑审批链接在手机上落到普通审批。P6 核实为同源、无状态冲突，只是控制重复。核实结果、整改方案与分批见[产品信息架构整改方案](../../engineering/product-ia-remediation-plan-2026-11-06.md)。

类型：**重复**＝两处入口解决同一用户任务；**归属**＝放在与任务不符的分组；**可发现性**＝功能存在但难以找到；**一致性**＝桌面与移动、页面与页面之间口径不一。

| --- | --- | --- | --- | --- | --- |
| P1 | 重复 | `/runs` 全部运行 | 页面描述为“oncall 排障的统一入口”，但侧栏隐藏，除导航和路由定义外没有任何页面链接到它；侧栏另有“作业运行”“工作流运行”两个入口 | 声称的统一入口实际找不到，同一任务有三个页面 | 二选一：作为运行监控首个入口显示，并把作业/工作流运行降为它的页签；或下线该页，只保留重定向 |

## 隐藏入口分流（P8 细化）

P8 的整改分流以[产品信息架构整改方案](../../engineering/product-ia-remediation-plan-2026-11-06.md)为准；下表保留为审查时的初步分类。

原则：隐藏不是问题，“只能靠 ⌘K 找到”才是问题。每个隐藏入口应至少有一个能从菜单点到的位置：下钻链接、所属页面的页签，或中心页卡片。菜单按角色过滤，评估菜单长度要按角色看，租户用户实际可见项远少于 56。

| 处理方式 | 入口 | 菜单净变化 |
| --- | --- | --- |
| 保持隐藏：上下文下钻页 | 作业步骤、编排设计器、血缘证据、批次日重放（从批次日页发起）、配置批量导入（从作业定义进入）、流水线观测、到达组 | 0；需确认每个都有上游链接 |
| 并为已有页面的页签 | 操作审计 → 审计页（替代“文件审计”菜单项）；资产新鲜度 → 作业监控策略；事件目录 → 通知与投递；容量画像 → 使用统计；Worker 指纹、自定义任务类型 → Worker；分片目录 + 租户分片 → 一个“分片”页 | 0 或 -1 |
| 收进“平台设置”中心页（一个菜单项，内放卡片） | 系统参数、API Key、标签、原子节点配置、维护设置（现为可见项，一并收入） | +1 -1 = 0 |
| 移出菜单体系 | AI 助手 → 顶栏图标；告警路由（预留）→ 下线或仅审计员可见 | 0 |
| 改为可见 | 运维诊断、租户配额（仅平台管理员可见） | +2（只对平台管理员） |

结合 P2（权限自查并入我的账户，-1），平台管理员的可见菜单数基本持平，租户角色不增加。

## 核对后不建议合并

- 文件模板 / 文件渠道 / 到达组：同一文件链路的不同配置对象，已在 11-02 审查中确认分工。
- 通知与投递 / 告警事件：一个配置投递，一个处置事件。
- 发布管理 / 审批中心：发布单只提交审批，审批在审批中心完成，不是重复审批。
- 作业步骤隐藏：属于从作业运行下钻的上下文页，隐藏合理。

## 建议优先级

1. **先做（低成本、收益明显）**：P2 合并权限自查，P4 资产新鲜度归位，P9 移动端审批对齐。
2. **需要产品决定**：P1 统一运行入口的方向，P7 自助服务的目标用户。
3. **需要核实后端**：P6 触发器与工作流调度是否同源。
4. **结构性调整**：P3、P5、P8 一起做，涉及分组、后端 `menu.yml` allowlist 和四角色可达性回归。
