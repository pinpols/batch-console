## 已发现的统一性问题

1. [ListPageQueryBar](../../../src/components/table/ListPageQueryBar.vue) 在多字段模式中将一般字段容器约束到 128–200px，并以 `!important` 让控件填满容器，覆盖调用方 `query-w-*` 的显示意图。三字段及以下又默认切换左侧标签和另一套宽度规则。同一字段在不同搜索栏可能表现不同；最终宽度还需 computed style 证实。
2. [FileList](../../../src/views/file-center/FileList.vue) 的文件名、ID 和 Trace 筛选分别声明不同宽度，但上述布局可能使这些区别失效；[LineageEvidence](../../../src/views/observability/LineageEvidence.vue) 使用 `query-w-320`，当前全局样式没有定义该档位。现有样式注释中的默认宽度也与变量值不一致。
3. [全局表格样式](../../../src/styles/element-override.css) 默认单行省略；例如 [WorkflowRunList](../../../src/views/monitor/WorkflowRunList.vue) 的 Trace ID、[BatchDayWindow](../../../src/views/scheduler/BatchDayWindow.vue) 的 Workflow Code / Request ID 等列没有在列上明确配置完整值提示。是否存在其他查看入口及实际截断需逐页验证。
4. [ListPageQueryBar](../../../src/components/table/ListPageQueryBar.vue) 与 [OpsFilterToolbar](../../../src/components/table/OpsFilterToolbar.vue) 的搜索、重置、刷新顺序不一致。日期预设、双端日期时间与时区属于组合控件，不能按普通短输入安排空间。
5. [CopyableText](../../../src/components/common/CopyableText.vue) 可复用复制功能，但当前以可点击 `span` 触发且图标只在 hover 显示；键盘、触屏可发现性和无障碍名称需要补齐后，才能作为长值统一入口。
6. 长度契约另有一处明确不一致：[ShardCatalogList](../../../src/views/ops/ShardCatalogList.vue) 允许数据库名输入 128、凭据引用输入 255，而配对后端 `ConsoleBusinessShardCatalogController.UpsertShardCatalogRequest` 分别限制 64 和 128；页面保存时直接提交。前端可能允许用户输入随后被后端拒绝的值。核查基于当时后端 HEAD `fb7ec82a05bb3c3d722afe243e2db22a656e1730` 的 Controller，不代表已完成修复。

## 推荐方案

### 控件和搜索栏

- 根据用途而不是 `maxlength` 建立少量语义尺寸：短值（布尔、状态、端口、短格式符）、常规值（名称和编码）、长标识（Trace、请求 ID、路径）以及范围/全文（日期范围、URL、长说明、JSON）。以下仅为首轮验证范围：短值约 96–144px、常规约 200–280px、长标识约 320–480px；受容器约束并允许 `max-width: 100%`。日期时间范围根据预设、起止时间和时区的真实文字测量，空间不足时整组换行。
- 在现有运行时 token 和共享搜索栏上定义字段容器的 `min-width` / `flex-basis` / 最大宽度，控件填满自身容器；避免全局覆盖调用方意图。少字段与多字段使用稳定、一致的标签位置，必要的紧凑样式由页面明确选择，不依靠字段数量突然切换。迁移期间为现有 `query-w-*` 明确兼容策略，不能让已有表单静默变窄。
- 搜索、重置、刷新按钮的顺序与主次样式统一；空间不足时可换行但不遮挡字段或表格。高级筛选和收起状态保留已输入、已生效条件及键盘操作，不为缩短工具栏丢状态。
- 校验上限以对应后端 DTO、OpenAPI 和持久化约束为准；确认上限按字符、代码单元还是字节计算。输入框宽度不等于最大长度：128/256 字符的名称或编号允许完整粘贴和水平编辑，1024 字符 URL、长描述与 JSON 提供合适的多行/展开体验。密码、密钥等敏感值不默认展开或复制。

### 只读内容和表格

- 短状态、序号、时间及数值列设置容纳实际格式和中英文表头的保底宽度；名称/说明列使用 `min-width` 和弹性空间；操作列按实际按钮、权限和语言设置宽度，避免为了统一挤占主要业务内容。
- 编码、长 ID、文件名、路径等可截断，但必须有可键盘/触屏访问的完整查看方式；允许复制的字段复制原始完整值。错误、JSON 等长内容用详情/抽屉查看，敏感字段遵循权限和脱敏约束，不把 hover tooltip 当成唯一入口。
- 优先复用 `ProTable`、`ListPageQueryBar`、`DatetimeColumn` 和改进后的 `CopyableText`，通过少量语义配置迁移；不要按 `maxlength × 固定字符宽` 或对全部列强制同宽。必要时保留横向滚动、列显隐和固定操作列，但避免固定列遮挡主要内容。

## 建议实施和验收顺序

1. 固定真实后端字段约束和典型值，优先修复已确认的 Shard Catalog 长度契约差异；先确认共享搜索栏、表格/复制组件的 API、不同标签模式和响应式行为；建立语义尺寸并兼容现有页面。
2. 先迁移文件列表、运行监控、血缘查询、作业日和模板编辑等代表页，再按字段类型盘点其余页面；记录仍未迁移项与业务例外。
3. 在实际浏览器核对 1440、1280、1024、768 和移动视口，中文/英文、深浅主题及 200% 缩放；对照 computed style 和截图验证字段不抖动、按钮不遮挡、日期可编辑、表格可滚动。
4. 用空值、常见长度、边界/超长值、CJK/emoji、长路径、Trace/Request ID 和超长错误分别验证输入、完整查看、复制、清空、重置、键盘及屏幕阅读器；复核角色与敏感信息边界。区分 mock 与真实后端，失败或跳过不计通过。
