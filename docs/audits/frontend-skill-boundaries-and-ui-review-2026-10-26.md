## 职责与去重

| 入口 | 主责 | 边界 |
|---|---|---|
| `cross-repo-governance-review` | 双仓覆盖、责任和证据汇总 | 前端保留轻入口，20域/模式/交付格式引用配对后端权威总控；不复制两份独立清单 |
| `frontend-quality-review` | 前端代码Bug/变更与跨领域综合质量 | Bug给出触发、预期/实际、影响、根因；UI/规约细项按需使用专项，不重复审同一页面 |
| `frontend-engineering-governance` | 架构/代码规约、可维护性、门禁及供应链 | 普通门禁通过不替代语义规约；Bug交质量审查，视觉/交互交UI专项 |
| `frontend-ui-ia-review` | UI、信息架构、交互、美观与视觉一致性 | 维护具体常见问题及验证方法；区分功能Bug、可用性、规范偏差和视觉建议 |
| API/状态/i18n/测试等既有专项 | 各自领域的深查与验证 | 复用同基线证据，避免所有入口各跑一轮；交付与环境操作遵循原授权 |

`frontend-i18n-accessibility`补实际DOM名称、键盘/语言反馈及动态Locale边界；`frontend-testing-ci`补视觉/交互验证的场景选择、基线解释和真实业务证据边界。

## 任务路由反例核对

人工核对6类请求：只查前端Bug→质量技能Bug模式；只做前端规约→工程治理；只审美观/交互→UI专项；综合质量→按影响调用专项并共享证据；仅查语言/DOM名称→i18n专项；明确双仓周期→配对后端权威总控。旧截图/axe统计、静态门禁和历史PASS不转成当前页面通过。该核对是技能文本/职责审查，不是独立Agent前向测试或实际浏览器操作。
