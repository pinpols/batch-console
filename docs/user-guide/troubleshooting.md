# 常见问题

> **关注角色**：全部角色
> **操作级别**：排查指南
> **反馈最小信息**：环境、时间、租户、页面、对象标识、Trace ID、错误码

## 页面没有数据

按以下顺序检查：

1. 当前租户是否正确。
2. 时间范围和浏览器时区是否覆盖目标记录。
3. 状态段、关键字和已保存筛选是否过窄。
4. 实时监控是否暂停，最后更新时间是否变化。
5. 空状态是“暂无数据”“筛选无结果”还是“加载失败”。
6. 使用重置后重新查询，不要反复刷新同一组错误条件。

## 菜单或按钮不见了

- 先阅读[角色与权限](./roles-and-access.md)。
- 页面入口由后端菜单、前端能力档和 authority 白名单共同过滤。
- 权限刚调整时退出并重新登录。
- 对象状态不允许操作时，按钮可能禁用或隐藏。
- 不要通过手工拼 URL 判断自己应当有权限；接口会再次校验。

## 提示 `401`

通常表示未登录、会话过期、账号状态变化或认证信息无效。保存未提交的非敏感内容后重新登录。若刚完成密码修改或账号权限调整，重新登录属于正常流程。

## 提示 `403`

表示当前身份没有该接口权限或超出租户范围。核对角色、租户和对象，不要重复提交。若业务确需操作，由账号管理员按最小权限调整授权。

## 提示 `404`

可能是对象已删除、当前租户不可见、链接版本过旧或环境未部署该能力。返回列表重新查找，不要继续使用收藏的旧详情链接。

## 提示 `405`

表示请求方法与服务端端点不匹配，通常属于前后端版本或接口契约问题。记录页面、动作、时间、Trace ID 和前后端版本，交由研发核查；刷新页面通常不能根治。

## 提示 `409`

通常表示对象版本冲突、重复请求或状态已被其他操作改变。刷新对象详情，确认最新状态后再决定是否重新提交。不要在未理解冲突原因时连续点击。

## 提示 `5xx` 或网关错误

1. 记录 HTTP 状态、错误码和 Trace ID。
2. 确认是否只有单个页面失败，还是所有接口都失败。
3. 检查控制台健康状态或联系值班人员。
4. 写操作发生错误时先查运行或审计结果，避免因重复提交产生副作用。

## 登录页提示控制台服务不可用

该提示只在网络不可达、请求超时或服务端 `5xx` 时出现，账号或密码错误不会触发。页面会保留已填写的账号信息：

1. 本地开发确认后端服务和 Vite 代理目标已启动。
2. 部署环境确认网关、控制台 API 和健康检查状态。
3. 点击“重新连接”；不要连续提交，也不要为了绕过提示修改浏览器认证信息。

## 文档服务未启动

顶栏文档入口和页面内文档抽屉会先探测文档服务。不可用时会进入统一降级页，控制台业务功能不受影响。

- 本地只执行 `npm run dev` 不会启动文档站；使用 `npm run docs:serve` 启动统一文档预览，或使用 `npm run dev:all` 同时启动控制台和一个文档站。
- 从控制台同源地址 `/docs/` 访问，前端文档位于 `/docs/frontend/`。内部预览端口 5174 只供本地代理使用。
- 生产镜像构建会校验文档产物；若部署后仍进入降级页，检查 `/docs/` 静态资源映射和认证子请求配置。

## 中英文切换不完整

语言切换只翻译前端维护的界面文案。业务名称、用户输入、后端自由文本和部分错误原文可能保持原语言。如果固定按钮、表头或说明未切换，记录页面路径、当前语言和未翻译文本，按前端 i18n 缺陷反馈。

## 深色模式颜色异常

先确认主题设置是浅色、深色还是跟随系统，并刷新一次页面。如果只有某个组件不可读，记录主题、页面路径和截图；不要通过浏览器强制改色插件作为验收依据。

## 如何提交有效问题

建议使用以下模板：

```text
环境：
发生时间与时区：
账号角色：
租户：
页面与操作：
对象编码 / 实例 ID：
Trace ID：
HTTP 状态或错误码：
预期结果：
实际结果：
是否可稳定复现：
```

不要附带密码、Secret、Cookie、完整 Authorization header 或完整 API Key。
