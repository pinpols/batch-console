# 角色与权限

> **关注角色**：全部角色；账号管理员重点阅读
> **操作级别**：只读说明
> **关键结论**：四类正式业务角色、三档前端展示能力、后端接口授权三者不能混用

## 四类正式角色

| 角色                           | 数据范围 | 常见可写能力                                 | 常见只读能力             | 不应承担的职责                     |
| ------------------------------ | -------- | -------------------------------------------- | ------------------------ | ---------------------------------- |
| `ROLE_ADMIN` 平台管理员        | 跨租户   | 平台配置、租户、全局治理、高风险运行处置     | 全平台运行与审计         | 代替业务租户完成日常数据确认       |
| `ROLE_AUDITOR` 平台审计员      | 跨租户   | 不执行审批或配置变更                         | 审计、配置历史、运行证据 | 修改平台配置、业务定义或执行审批   |
| `ROLE_TENANT_ADMIN` 租户管理员 | 当前租户 | 租户账号、作业流程、文件配置、审批与受控治理 | 本租户运行、告警与审计   | 跨租户管理或平台级维护             |
| `ROLE_TENANT_USER` 租户用户    | 当前租户 | 被授权的自助触发、API Key 等有限操作         | 本租户日常运行与告警     | 租户账号授权、全局配置和高风险处置 |

账号、JWT、菜单和前端只接受上述四类正式角色。

## 为什么前端只有三档能力

前端将后端权限码映射成 `ADMIN / OPERATOR / VIEWER`，用于基础菜单和组件展示：

| 前端能力档 | 常见来源                                | 用途                     |
| ---------- | --------------------------------------- | ------------------------ |
| `ADMIN`    | `ROLE_ADMIN`                            | 展示平台管理与高风险入口 |
| `OPERATOR` | `ROLE_TENANT_ADMIN`                    | 展示租户管理入口       |
| `VIEWER`   | `ROLE_AUDITOR`、`ROLE_TENANT_USER`、未知权限安全回退 | 展示只读与受控自助入口 |

这只是界面能力粗分。`ROLE_AUDITOR` 与 `ROLE_TENANT_USER` 虽同为 `VIEWER`，具体接口仍不同：租户用户可以使用自助入口，审计员可以跨租户读取审计证据。前端还会结合后端下发菜单与页面 authority 白名单过滤入口，最终接口仍由后端 `ROLE_*` 校验。

## 如何判断权限问题

1. 查看右上角账号菜单中的用户名和角色标识，确认登录账号是否正确。
2. 核对当前租户。租户角色固定在自己的租户范围内，通常不能切换到其他租户。
3. 使用全局搜索或侧边栏查找页面。搜索不到不代表页面故障，可能是后端未下发该菜单。
4. 页面可见但按钮不可用时，检查对象状态、表单完整性和当前角色；不要仅凭页面可见性判断有写权限。
5. 返回 `403` 时按权限不足处理，不要通过修改 URL 或请求绕过。

## 账号授权建议

- 日常观察优先使用 `ROLE_TENANT_USER`，不要长期使用平台管理员账号值班。
- 租户内配置和审批使用 `ROLE_TENANT_ADMIN`。
- 合规与跨租户取证使用 `ROLE_AUDITOR`，避免附带不必要的写权限。
- 平台级维护使用 `ROLE_ADMIN`，完成后退出或切回低权限账号。
- 同一账号可能包含多个 authority；高权限 authority 会扩大数据范围和操作能力，应按最小权限配置。

## 权限变化何时生效

账号角色、停用状态或租户绑定发生变化后，旧会话可能仍显示缓存菜单。建议退出并重新登录，使后端重新签发会话并返回最新菜单。若仍不一致，记录用户名、租户、目标页面、发生时间和 Trace ID，交由管理员核查审计记录。
