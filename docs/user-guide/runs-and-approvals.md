# 运行与审批

> **关注角色**：运维值班、`ROLE_TENANT_ADMIN`、`ROLE_ADMIN`、`ROLE_AUDITOR`
> **操作级别**：查询为低风险；重试、取消、审批和批次日重放为受控或高风险操作
> **典型入口**：工作台 → 审批中心；运行监控 → 作业运行、工作流运行

## 顶层运行与关联作业

“全部运行”和“工作流运行”用于定位顶层 Workflow；作业实例是其执行或观测关联对象。先从详情确认 Workflow Run、Job Instance 与业务日期的关联，再判断恢复目标。不要用父 Workflow 的 Trace ID 替代具体作业实例标识。

## 查询作业运行

1. 进入“作业运行”，先选择状态段。
2. 按作业开始时间设置日期范围；业务日期在运行行中单独展示，不能用未来业务日过滤当天实际开始的作业。
3. 按作业编码或 Trace ID 进一步缩小范围。
4. 打开行详情查看步骤、参数摘要、日志和关联标识。
5. 实时监控开启时确认最后更新时间；暂停时使用刷新按钮获取最新状态。

查不到实例时依次检查租户、时间范围、时区、状态筛选、作业编码和是否误用了父工作流 Trace ID。

## 理解运行状态

Workflow 详情的依赖图来自该次运行的冻结定义，图上的状态与关联作业由首次快照和后续推送更新。“执行 / 等待 / 失败节点”可以同时列出多个节点；内部调度游标不代表实际执行位置。宽图默认适应画布，可缩放查看。开始、结束时间使用后端持久化时间；结束时间未知时保持为空，不根据进度比例推算。

- **运行中**：后端仍在调度或执行，不要因页面暂时无变化重复触发。
- **成功**：实例完成，但仍需按业务要求确认输出或文件交付。
- **失败**：先查看失败步骤、错误码和 Trace ID，再判断重试是否安全。
- **已取消**：取消请求已生效；外部系统副作用是否已发生需单独确认。
- **等待审批/等待条件**：不是卡死，先到审批中心或检查日历、窗口、文件到达条件。

## 重试与取消

作业实例重跑、批量重试／取消、暂停／恢复、分区重试及终止仅平台管理员可执行，移动作业详情遵循同一权限。租户管理员可查询运行并处理其获授权的审批，配置写权限不等于运行控制权限。

执行前确认：

- 目标实例和租户正确；
- 作业是否幂等，重复执行是否会重复扣款、发信、写文件或调用外部接口；
- 失败原因已经消除；
- 是否需要从失败步骤重试，还是创建全新运行；
- 是否存在并发中的同业务实例。

Workflow 详情会按根运行和失败节点状态提供不同的重放操作。整轮重放要求根运行已终态；失败作业节点重放要求根运行与对应 Job 节点均失败，并具有有效作业实例。按页面提供的动作选择恢复范围，不能把单作业重试、节点重放与整轮重放当作同一动作。

节点与整轮重放申请仅平台管理员可提交，后续审批遵循审批页面现有角色边界。外部结果未知时先核对实际执行结果，预览会拒绝继续重放；不能把未知结果当作普通失败直接重做。

死信在“综合查询”的“死信队列”页签查看。重放及批量选择仅平台管理员可用，维护冻结时不可提交；切换租户或写权限变化后应重新选择目标。若外部结果未知，只有独立核实外部动作未执行后，才能勾选核实项并填写原因和证据引用，提交后仍须审批；不能仅凭本地作业失败判断外部未执行。

取消运行中的作业可能先得到“已请求取消”；收到请求不等于所有任务立即停止。应继续核对实例终态和外部副作用。

提交后不要只看成功提示，应等待列表刷新并核对新状态、重试次数或新实例标识。响应丢失时保留请求身份并先核对已有运行，避免无依据重复触发。

## 审批中心

审批中心同时承载普通审批与补跑类审批。默认列表只展示决策所需摘要，完整上下文在行详情中查看。补跑列表切换租户后立即关闭原详情；等待新列表完成后再选择，旧租户或旧页响应不覆盖当前页。

1. 选择待处理状态，按时间或类型筛选。
2. 打开详情，核对申请人、租户、对象、原因、影响范围和关联运行。
3. 对高风险请求检查重复申请与当前对象状态。
4. 单条审批使用行操作；批量审批前确认筛选结果没有混入不同业务目的的请求。
5. 提交后确认状态变为已批准或已拒绝，并检查后续运行是否真正开始。

审批入口向平台管理员和租户管理员开放；审计员没有审批入口。提交与批准须符合后端的申请人、审批人和租户校验，不能用配置写权限代替审批资格。

## 批次日重放

批次日重放用于按业务日补跑全部候选、失败项、指定作业或输出结果。它可能产生大量实例或重复业务副作用。

同页的“结果版本治理”区域可按完整业务键查询版本、当前生效版本及元数据详情。原始结果载荷不会展开；ADMIN 和租户管理员可对待处理版本执行提升或拒绝，其他角色只读。执行后以重新查询的状态为准。

操作顺序：

1. 确认业务日、时区和批次窗口。
2. 选择最小必要范围，优先指定失败对象而非全量。
3. 阅读预估或预览结果，核对候选数量。
4. 明确是否需要审批；自动审批不等于无需风险确认。
5. 提交后记录会话或请求标识。
6. 在作业运行、审批中心和审计记录中跟踪最终结果。

## 批次日窗口补跑的请求状态

管理员在批次日窗口发起 Catch-up 时，页面在发送前保存原请求键。响应丢失或刷新页面后，可在原用户、租户、业务日和日历下查询请求状态和逐项回执；查不到仅表示当前没有观察到记录，不能证明未提交，也不能换键重发。只有查询到批次状态为 COMPLETE 并人工核对后，才能清除本机保存的请求键并发起新请求。UNKNOWN 或 IN_FLIGHT 项可以核对原回执：人工审批策略核对审批，自动策略核对 Trigger；服务端按首次冻结的身份和载荷验证，确认后展示回执。查不到或身份不一致时保持原状态，不会发起新的补跑。批次为 PREPARED 或 RUNNING 且没有 UNKNOWN、IN_FLIGHT 项时，管理员可以点击“继续提交待处理项”；服务端沿用首次冻结的目标、原申请人与项目键，已确认项不会再次提交。接续结果不确定时重新查询原请求，不能换键重发。如果一直查不到原回执，请保留请求键并结合服务端记录人工排查；不能把查不到当作未提交。

请求键保存在当前浏览器本地存储，清除浏览器数据、更换设备或浏览器会丢失该本地记录；不同管理员或浏览器之间不共享此页面保护。存储不可用时页面阻止提交。该保护不代替服务端并发控制，也不代表作业或审批已经完成。

## 交接记录

值班交接至少记录：租户、业务日、对象编码、实例 ID、Trace ID、当前状态、已采取动作、审批单和下一步负责人。避免只写“已重试”而没有可验证标识。

## 运行 DAG 与进度

运行图默认适应画布，可继续缩放查看。主档的“执行／等待／失败节点”来自同一份冻结节点快照，可能同时显示多个并行节点；没有当前执行或失败位置时显示空值，不把根运行内部的结束游标误当作已执行 END。

文件作业详情展示平台固定阶段及最新尝试的状态、尝试序号和已处理记录数。Worker 中断后可按 checkpoint 续跑；当前尝试成功不抹去历史中断记录。查询历史步骤时应结合尝试序号、原因码和父作业最终状态判断，避免把已中断的旧尝试当作仍在执行的工作。

PROCESS阶段有正式处理计数时显示实际条数，COMMIT显示实际发布条数；处理600条不代表已发布600条。无可靠计数时显示“—”，实际0条显示0，不根据运行时间推算百分比。

Workflow运行详情和“完整DAG”入口展示本次运行冻结的节点及依赖边。修改当前流程定义不会把历史运行改画成新定义；缺少冻结图时显示不可用提示。并行节点分别显示状态、计划分区的已结束数和当前步骤，表格提供错误/跳过原因码与作业实例入口。作业阶段/分区进度放在作业详情，Pipeline当前阶段放在文件Pipeline观测页；租户今日统计留在运维总览。

“已结束节点”包括成功、失败、跳过、取消或终止，与“成功节点”计数不同。已结束/已创建任务只说明当前已生成任务，不是未来全部任务量；分区总量未确定时不显示百分比。跨日依赖等待会独立标识，成功、失败、条件和始终依赖由连线文字区分。

进度由服务端推送完整状态，初始加载和重连时补查。失联时保留最后快照、显示警告和最后更新时间，并低频补查；不要把断线快照当作最新状态。运行暂停停止后续派发/推进，在途工作继续收尾，恢复后按原运行继续。

## 实例与告警操作的上下文保护

在实例详情、批量操作或告警原因输入期间切换租户/实例，原确认不再有效；剩余排队请求停止，需在当前目标重新确认。已经发出的请求仍由服务端权限、状态和幂等边界裁决，前端不能撤销已受理副作用。

作业的部分失败、演练成功和演练失败均属于终态，不提供批量取消；允许的重试/恢复仍按各入口的业务策略判断。告警查询随当前租户更新，旧回包不覆盖当前列表或计数。Workflow 运行深链的编码与分页在首次请求前解析，编码须先定位到当前租户内的定义 ID。


## 审批、分区与等待的确认上下文

在审批原因、批量确认、分区重试/取消或日历等待原因窗口打开后，切换租户或离开原实例会使确认失效；即使再切回原租户，也要重新确认。写权限撤销或进入维护时不再继续提交。当前租户的正常操作沿用原请求和幂等规则。

切换租户立即清除原审批列表、选中项和详情，迟到响应不恢复它们。 批次日补跑提交期间切换租户或登录上下文后，原请求的迟到回执不会关闭当前弹窗或在新上下文显示提交成功；原请求键仍保留在原上下文供回查。分区读取失败显示错误，不能根据空表判断分区已全部结束。已发送的审批、分区和等待请求仍须结合服务端回读与审计确认结果，前端切换不能撤销已经受理的动作。

## Workflow 与运维确认

危险确认在租户、登录主体、权限或维护状态变化后按取消处理，需在当前上下文重新确认。Workflow 详情在离开原运行后清除旧信息，迟到节点列表或重放预览不会恢复旧目标；即使再返回原运行，也不能继续先前确认。

Worker 排空、接管、强制下线和预热使用选中租户与当前 Worker 状态。切换后旧响应不刷新新租户列表；调度快照和渠道列表也清除旧数据。全局调度暂停/恢复依旧作用于全局，不能将当前租户筛选理解为只暂停该租户。
