# 运行与审批

> **关注角色**：运维值班、`ROLE_TENANT_ADMIN`、`ROLE_ADMIN`、`ROLE_AUDITOR`
> **操作级别**：查询为低风险；重试、取消、审批和批次日重放为受控或高风险操作
> **典型入口**：工作台 → 审批中心；运行监控 → 作业运行、工作流运行

## 查询作业运行

1. 进入“作业运行”，先选择状态段。
2. 设置日期预设或明确的开始、结束时间。
3. 按作业编码或 Trace ID 进一步缩小范围。
4. 打开行详情查看步骤、参数摘要、日志和关联标识。
5. 实时监控开启时确认最后更新时间；暂停时使用刷新按钮获取最新状态。

查不到实例时依次检查租户、时间范围、时区、状态筛选、作业编码和是否误用了父工作流 Trace ID。

## 理解运行状态

- **运行中**：后端仍在调度或执行，不要因页面暂时无变化重复触发。
- **成功**：实例完成，但仍需按业务要求确认输出或文件交付。
- **失败**：先查看失败步骤、错误码和 Trace ID，再判断重试是否安全。
- **已取消**：取消请求已生效；外部系统副作用是否已发生需单独确认。
- **等待审批/等待条件**：不是卡死，先到审批中心或检查日历、窗口、文件到达条件。

## 重试与取消

执行前确认：

- 目标实例和租户正确；
- 作业是否幂等，重复执行是否会重复扣款、发信、写文件或调用外部接口；
- 失败原因已经消除；
- 是否需要从失败步骤重试，还是创建全新运行；
- 是否存在并发中的同业务实例。

提交后不要只看成功提示，应等待列表刷新并核对新状态、重试次数或新实例标识。

## 审批中心

审批中心同时承载普通审批与补跑类审批。默认列表只展示决策所需摘要，完整上下文在行详情中查看。

1. 选择待处理状态，按时间或类型筛选。
2. 打开详情，核对申请人、租户、对象、原因、影响范围和关联运行。
3. 对高风险请求检查重复申请与当前对象状态。
4. 单条审批使用行操作；批量审批前确认筛选结果没有混入不同业务目的的请求。
5. 提交后确认状态变为已批准或已拒绝，并检查后续运行是否真正开始。

审计员能否参与某类审批以后端策略为准。只读审计场景应查看记录，不应为了方便授予平台写权限。

## 批次日重放

批次日重放用于按业务日补跑全部候选、失败项、指定作业或输出结果。它可能产生大量实例或重复业务副作用。

操作顺序：

1. 确认业务日、时区和批次窗口。
2. 选择最小必要范围，优先指定失败对象而非全量。
3. 阅读预估或预览结果，核对候选数量。
4. 明确是否需要审批；自动审批不等于无需风险确认。
5. 提交后记录会话或请求标识。
6. 在作业运行、审批中心和审计记录中跟踪最终结果。

## 交接记录

值班交接至少记录：租户、业务日、对象编码、实例 ID、Trace ID、当前状态、已采取动作、审批单和下一步负责人。避免只写“已重试”而没有可验证标识。
