# 平台治理

> **关注角色**：`ROLE_ADMIN`、`ROLE_TENANT_ADMIN`、`ROLE_AUDITOR`
> **操作级别**：多数为配置写入或安全敏感操作
> **典型入口**：调度与资源、平台管理

## 租户与账号

### 平台管理员

- 创建和维护租户，确认租户编码、显示名和初始管理员。
- 跨租户查看时始终核对顶栏租户，避免在错误作用域执行写操作。
- 分配角色遵循最小权限；审计员不附带写角色，租户账号不授予平台角色。

### 租户管理员

- 仅管理当前租户账号。
- 新建账号时只选择 `ROLE_TENANT_ADMIN` 或 `ROLE_TENANT_USER`，其他角色码会被后端拒绝。
- 重置密码后通过安全渠道通知用户，并提醒其登录后修改。
- 停用账号前确认是否仍有值班、自动化或 API Key 依赖。

账号列表中的总数、启用、停用是摘要，不代替角色和租户范围检查。高频操作使用统一的小号行操作，完整信息在编辑或详情中查看。

### OIDC 身份绑定

用户列表的 OIDC 身份管理仅供平台管理员使用，并始终限定当前选中的租户。管理员可把外部提供方的精确 subject 绑定到已有本地账号，或解除已有绑定；此操作不会创建账号、授予角色或显示提供方凭据。确认登录提供方已启用，并核对 subject 与目标账号后再提交。

## Worker 与指纹

Worker 管理用于判断执行节点是否在线、版本是否一致、能力是否满足任务要求。

- 先看在线状态、最后心跳和正在执行量。
- 再看版本漂移摘要和指纹差异。
- 下线或隔离 Worker 前确认正在运行的任务和可用容量。
- 前端不直接修复 Worker 软件或网络；节点升级、进程管理和基础设施处置属于部署运维职责。

## Atomic 节点参数预设

Atomic 节点配置中心按执行器展示内置参数 schema 与运行门控信息。ADMIN 和 TENANT_ADMIN 可在已选租户内读取、保存并应用参数预设；平台管理员操作前应核对顶栏租户。列表与映射参数请填写 JSON 数组或对象，页面会在保存时校验格式；Shell 命令和参数中不要填写令牌、口令或带凭据的 URI。保存仅创建可复用参数，不会执行节点或发布工作流；后端会再次校验字段类型并拒绝明确的凭据语法。接口当前支持查询和新建，不提供编辑或删除。

Worker 卡片也提供当前已认领任务的只读明细，用于确认任务状态和关联作业/分区。这里不显示任务载荷、结果正文或原始错误内容；发现终态不一致时再到平台诊断查看父子健康摘要。

## 调度、日历与窗口

- 调度快照用于观察当前调度状态，不是配置编辑页。
- 业务日历定义可运行日期，批次窗口定义时间范围。
- 批次日主视图适合按日历检查状态，表格明细用于精确筛选和审计。
- 修改日历或窗口前评估未来触发、等待实例和补跑计划。
- 重开或关闭批次日属于高风险操作，以后端授权和审批策略为准。

### 批次日治理

批次日列表和窗口页的“批次日治理”打开同一个抽屉。管理员、审计员和租户管理员可读取补扫预览与历史缺口；治理动作仅管理员可执行。补扫预览显示当前日历业务日期、游标来源、下一轮日期和剩余日期数；它不是已执行结果，也不负责查明游标之前的历史遗漏。

历史缺口查询最多包含90个自然日，结束日期不能晚于该日历当前业务日期。缺少批次日记录只表示待人工复核候选，不代表漏跑，也不会自动创建或补跑；可从候选进入对应日期窗口。

管理员可按当前状态冻结、人工放行、跳过、重开、关闭或确认空日结算，并暂停/恢复自动补扫。人工放行会置为 `MANUAL_RELEASED`，不是仅解除冻结；跳过不代表成功。空日结算还须服务端检查无作业、无依赖等待与未收敛计划。所有动作填写原因，服务端记录认证操作者，提交后重新读取持久状态；冲突由服务端拒绝。

响应丢失时，原命令按当前用户、租户和日历保存在本标签页，刷新页面后恢复原幂等键。先在抽屉刷新核对，再重试原命令；结果未确认时不允许改成另一条命令。记录损坏、存储不可用或超过23小时安全重试期限会阻止新请求，需人工核对操作审计。成功或明确拒绝后才清除对应记录；旧确认不会删除后续新命令。

## 队列、配额与容量

- 资源队列描述任务竞争和执行资源分组。
- 配额策略限制租户或业务的并发和资源使用。
- 容量画像应结合趋势、排行和 P95 查看，表格用于追溯具体明细。
- 调整配额前检查当前排队量、峰值、失败率和其他租户影响。
- 前端只提交控制面配置，不直接扩缩容基础设施。

## API Key 与 Secret

- API Key 创建后按页面提示一次性保存，不在文档、工单、日志或聊天中粘贴完整值。
- 撤销前确认调用方和轮换计划；撤销后旧 Key 不应继续工作。
- Secret 页面只管理引用和受控更新，不应展示可长期复制的明文。
- 配置导出、同步和审计中出现的 Secret 通常应是引用或脱敏值。

## 配置发布与同步

复制源不能同时作为目标：更换源租户后，重合目标会移除，其他目标保留。提交前请核对目标集合；服务端也会在读取和写入前拒绝重合，避免清空源渠道的环境配置。租户/作业列表不能包含空值，类型列表不能包含null；可选列表留空仍表示原先的全部范围。

复制配置的差异、Overlay和作业矩阵对应当前输入，修改后应重新预览；关闭重开或切换账号后，旧结果不会恢复。复制与试运行在校验期间不可重复提交，这些预览和复制端点均使用POST，维护期间按服务端HTTP方法策略同时禁用。服务端复制已经发出时，关闭面板不会撤销业务，需按配置事实核对。

配置复制和同步导出读取完整集合，不受普通列表200条分页限制。作业矩阵可使用展示范围外的基准租户；仍只展示所选比较租户，基准缺少作业时会按缺失事实标记差异。

手写初始化 JSON 的目标租户、写入模式和试运行开关以面板选择为准，正文不能覆盖。初始化响应有失败租户或失败条目时面板保持打开，请先检查结果及已生效配置；试运行不显示正式完成提示。旧初始化或复制入口的连接/事务错误不表示未执行，也不具备下述同步页面的持久原请求恢复能力，核对配置后再决定如何处理剩余目标。

初始化校验期间修改输入、关闭面板、切换目标或账号、失去写权限或进入维护后，需要在当前上下文重新发起操作。已经提交的请求不会因关闭面板而撤销，请按服务端配置核对结果；迟到响应不会关闭重新打开的面板。

配置变更应遵循“编辑 → 校验 → 差异预览 → 审批或发布 → 验证 → 审计”的闭环。

- 审计员关注变更证据和差异，不承担日常发布写操作。
- 租户管理员只处理本租户配置。
- 跨租户或跨环境同步由平台管理员确认目标与环境字段。
- 发布成功后仍需检查运行侧是否加载新版本。

同步确认打开后修改环境、目标租户或粘贴 JSON，需要重新确认；导出环境或类型变化后，应重新导出再复制。预览仅对应当时的输入，编辑后等待新预览。同步超时或系统错误不能视为未执行。页面保留原命令并显示“核对原同步”；未找到审计或 RUNNING 仍表示结果待确认。不要发起另一条导入；如原响应未返回，可恢复原环境、目标租户和 JSON 后在23小时内“重试原同步”，请求身份保持不变。超过期限只核对，不再重试。

当前标签页刷新后仍可恢复原命令，配置正文不会保存，必要时需重新粘贴原 JSON。不同部署/API地址、账号和审计租户相互隔离。原导入返回确定结果或核对到审计终态后，才释放对应记录；核对不会重新应用配置。存储损坏或不可用时先检查浏览器会话存储，并通过同步审计核实，不能靠新请求绕过未知结果。

配置发布页切换租户会清空原创建草稿、版本对比选择和详情；请在当前租户重新选择并确认。创建校验、审批原因输入或回滚原因输入期间若切换租户、账号、写权限或进入维护，旧操作不继续发送；已经受理的请求仍需结合服务端回读和审计核对结果。

## 分片与租户放置

业务分片目录和租户放置属于平台级治理，只对 `ROLE_ADMIN` 开放。迁移或取消放置可能改变业务数据路由，必须与后端迁移流程、数据校验和回滚方案配套。控制台入口不是独立的数据迁移工具。
