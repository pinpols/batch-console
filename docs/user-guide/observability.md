# 可观测性与排障

> **关注角色**：运维值班、`ROLE_AUDITOR`、`ROLE_TENANT_ADMIN`、`ROLE_ADMIN`
> **操作级别**：查询为低风险；告警确认、投递重试和诊断操作需审慎
> **典型入口**：运行监控、告警与投递、平台管理 → 审计

## 推荐排障路径

1. 从运行总览或告警确认影响范围和开始时间。
2. 获取租户、对象编码、实例 ID 和 Trace ID。
3. 在 Trace 查询中查看关联请求与步骤。
4. 打开作业或工作流运行详情确认失败节点。
5. 若涉及事件投递，检查 Outbox 和通知投递记录。
6. 若涉及配置变化，检查配置变更和操作审计。
7. 只有在根因解除且业务幂等性明确后才重试。

## 告警

告警页按未处理、已确认等状态组织，并支持严重度、类型、时间和 Trace ID 筛选。

- **确认告警**只表示有人接手，不等于故障已恢复。
- **自动归档**或状态恢复不代表受影响业务已经补偿。
- 同一根因可能产生多条告警，先按 Trace ID、对象和时间聚合判断。
- 告警路由规则由有权限的管理员维护，修改后应验证目标渠道和抑制策略。

## 作业与 Workflow 时限策略

运行总览的 SLA 达标率以有截止时间的正式终态实例数为分母；按作业图表使用同口径的各作业分母。若终态实例缺少完成时间，它仍计入分母，但既不计为按时，也不计为违约；取消和 dry-run 不纳入该报表。可结合报表总数与分类计数排查此类异常记录。

“运行监控 → 作业监控策略”（`/observability/job-monitoring-policies`）可维护运行耗时、启动宽限和完成期限。完成期限在“绝对完成钟点”和“相对完成窗口”之间选择，切换时清除另一方式；0 或空钟点表示关闭。MANUAL 定义也可预先配置给 Workflow 子作业使用，运行没有真实计划或就绪依据时不会按创建时间判定迟到。列表展示已保存的配置，不把 Job 定义的旧调度类型当作是否启用的依据。

Workflow 定义列表的“监控策略”操作维护根运行自己的三类规则，与子 Job 策略独立；管理员和租户管理员可保存，其他有读权限的角色只读。规则只产生告警，不改变运行状态。运行耗时使用实际执行入口；排查时分别核对计划/就绪、派发、实际开始和完成时间。已发生的违约可能在扫描恢复后补报，告警入库仍不等于渠道送达；当前自动解除与可靠恢复投递的完整验收尚未完成。

## Outbox 与通知投递

Outbox 展示事件发布状态；发布成功只证明该发布阶段完成，不证明下游业务消费或最终收件人已经收到通知。业务终态通知的投递记录在“通知与投递”中单独查询。

1. 按状态和时间筛选失败记录。
2. 查看事件类型、聚合标识、重试次数和最后错误。
3. 确认下游已经恢复且重复投递可接受。
4. 执行授权的重试或补偿操作。
5. 刷新并确认状态变化；必要时到下游系统核实消费结果。

不要把 Outbox 失败简单归因于前端。前端展示后端状态，实际发布、投递、重试和去重由后端负责。

### 终态通知核对与人工重投

“通知与投递”中的终态记录区分来源、事件键、尝试次数与投递状态。Push 的供应商受理不等于设备展示或用户已读；禁用、试运行、无订阅等状态也不应写成送达成功。

仅已耗尽自动重试、没有下一次重试且没有有效投递占用的失败记录允许人工核对。先检查外部渠道的实际结果，再填写原因、核对依据并确认重投。页面使用原记录的尝试版本和请求身份提交，成功提示表示已排队，仍需跟踪后续投递终态与审计。

## Trace ID

Trace ID 是跨页面和跨服务关联一次请求或业务链路的首选标识。

- 从错误提示、实例详情、告警或 Outbox 复制完整 Trace ID。
- 使用专用输入框规范化空格和大小写，不手工截断。
- Trace ID 查不到时核对时间范围、租户、环境和遥测采样策略。
- 对外反馈时可提供 Trace ID，但仍需避免附带凭据、请求正文或个人敏感数据。

## 审计

审计页面回答“谁、在何时、对哪个租户和对象、执行了什么操作、结果如何”。

审计核查建议同时使用：

- 操作者与角色；
- 租户和对象标识；
- 操作类型与结果；
- 请求时间与 Trace ID；
- 变更前后摘要或关联版本。

前端筛选结果是查询视图，不替代后端审计留存。导出或截图应遵循组织的数据处理要求。

## 平台诊断

平台诊断、取证、缓存清理等入口通常只对 `ROLE_ADMIN` 开放。这类操作可能跨租户或影响平台状态，应在明确事故处置流程、影响范围和回滚方案后使用。租户级问题优先通过运行、Trace、Outbox 和审计定位，不升级为平台级写操作。

## 租户今日计划与执行

控制面板首屏提供业务日进度：计划触发、触发请求、Workflow运行、作业实例、已创建任务分别计数。默认日期使用部署的业务时区，可选择其他业务日；五层计数不能相加，也不能把已创建任务当作未来全部工作量。

多个日历或日程同时启用时，每条计划按自身日历解析的业务日期归入所选日期。CRON与FIXED_RATE的计划分别登记，再按同一业务日汇总；每个日程需独立满足对应日历截止时间和当前定义版本的覆盖条件，不能用某一条已覆盖代表全部。切到未来业务日时，已有未来计划并不表示批次日已经开启或覆盖完整。

状态图展示每个层级自身的状态分布，表格把“已结束”和“成功”分开。失败、跳过或取消可能使已结束比例达到100%，并不表示业务成功。计划缺少当前版本的投影覆盖水位或批次截止时间时，显示覆盖警告，不计算计划结束比例。零记录也不会显示100%。

页面优先消费服务端完整快照推送，断线保留最后数据、标注更新时间并补查；切换日期或租户会清空旧范围数据。这里查询热运行表，不包含已归档历史，也不包含尚未解析业务日期的计划记录。

总览图表只展示租户业务日汇总；作业阶段、分区和技术任务进度放在作业详情，Workflow节点及依赖放在运行详情/完整DAG，文件Pipeline阶段放在Pipeline观测页。它们复用对应运行快照，不另建一份重复统计。

## 持久化等待

调度快照页的“持久化等待”页签按租户查询 readiness 依赖等待和 Workflow 容量等待，可按类型、状态、Workflow 定义 ID 和业务日期筛选并分页。它是只读诊断视图，显示状态、日历/依赖/原因、等待与计划触发时间、截止或下次尝试时间及请求/Trace 标识；不返回原始启动参数，也不提供强制放行或重试。

READINESS 与 CAPACITY_ADMISSION 的状态集合不同；排查时先按等待类型解释状态，再用 Trace ID 或请求号关联运行与审计。平台管理员、审计员和租户管理员可按后端授权读取；切换租户后旧结果会清空。

## Worker 与取证诊断

Worker 管理卡片可查看当前租户中某个 Worker 已认领任务的状态、作业/分区标识、错误码和时间；不显示任务载荷、结果正文或原始错误信息。平台诊断中的终态子任务健康摘要用于发现父子状态不一致，不提供修复动作。

平台管理员可在诊断页按业务日期范围和可选作业编码生成取证包。创建前需确认范围；只允许下载状态为 `COMPLETED` 且具有校验摘要的包。若创建响应不确定，先查操作审计和后端记录，不要盲目重复导出；界面不会显示存储路径。
