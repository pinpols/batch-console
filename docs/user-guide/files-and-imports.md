# 文件与配置导入

> **关注角色**：`ROLE_TENANT_ADMIN`、`ROLE_ADMIN`；审计员关注配置与变更记录
> **操作级别**：文件查询为低风险；渠道、模板和租户配置包写入为高影响配置操作
> **典型入口**：文件；准备作业 → 租户配置包

## 文件处理对象

| 对象          | 用途                             | 常见检查                            |
| ------------- | -------------------------------- | ----------------------------------- |
| 文件渠道      | 定义文件从哪里来、如何识别和接收 | 协议、路径、凭据引用、租户边界      |
| 文件模板      | 定义文件格式、命名和字段规则     | 文件名模式、编码、字段、校验规则    |
| 文件列表      | 查询已发现或已处理文件           | 状态、到达时间、大小、关联 Pipeline |
| 到达组        | 汇总一组预期文件的到达进度       | 应到、实到、缺失、超时              |
| Pipeline 观测 | 查看文件处理链路进度             | 处理中、成功、失败与阻塞步骤        |

## 渠道和模板配置

1. 先确认当前租户和目标环境。
2. 使用清晰稳定的编码，不用显示名代替引用编码。
3. 凭据使用 Secret 引用；不要在备注、路径或普通 JSON 中粘贴明文密码。
4. 保存前验证模板与渠道组合是否匹配。
5. 使用小样本文件验证识别、解析、入队和最终输出。
6. 到文件列表、到达组和 Pipeline 观测确认全链路，而不是只确认配置保存成功。

### 人工入站文件

平台管理员和租户管理员可在文件列表选择已启用的接收通道并上传文件。系统先创建租户范围内的上传会话，再由应用托管接口接收文件，最后确认到达并按文件 ID 重新查询记录；只有读到持久文件记录后页面才显示成功。文件上传与到达确认均使用独立幂等身份。

需要触发文件组关联流程时，选择当前租户已启用的文件组目标、业务日、必需文件和IMPORT模板。对象内容写入后还须完成到达确认；确认前的对象不满足文件组扫描准入。确认成功只证明文件已登记，关联Workflow、Worker处理和业务落库仍需到运行详情与Pipeline观测分别核对。

若上传或确认后页面显示结果未确认，先用记录中的文件 ID 在文件列表核对状态和到达记录，再决定后续操作；不要直接重复提交可能已接收的文件。界面不会显示底层存储地址或上传路径。

## 租户配置包导入

导入向导采用“上传 → 预览 → 应用”三步，适合成套迁移作业、文件渠道、模板、Workflow、资源队列、日历、窗口等配置。新模板与配置包导出不再提供独立 Pipeline 定义/步骤表；Job 的系统 Pipeline 按类型解析。实际 sheet 和字段以后端模板 schema 为准。

旧配置包的阶段业务参数由后端预览兼容转换为 Job 默认参数；冲突和不受支持的值必须先修正，不能通过直接写 Pipeline 定义绕过校验。

### 1. 获取模板

- 下载配置包模板用于从零填写。
- 下载示例模板时可多选需要的业务场景；“全部场景”表示生成完整示例集合。
- 导出现有配置包适合做迁移基线，但导出文件仍需在目标环境预览校验。
- 先阅读字段填写说明，避免自行猜测枚举、引用顺序和必填规则。

### 2. 上传与预览

1. 上传 `.xls` 或 `.xlsx` 文件。
2. 等待后端解析完成，不要重复点击上传。
3. 在预览页检查每个 sheet 的新增、更新、跳过和错误数量。
4. 优先修复引用不存在、编码重复、枚举非法和必填缺失。
5. 对环境相关字段逐项检查，尤其是地址、渠道、队列、日历和 Secret 引用。

### 3. 应用

只有预览无阻断错误且影响范围可接受时才应用。应用后：

- 查看导入结果和失败明细；
- 抽查关键定义详情；
- 检查配置变更或审计记录；
- 用受控测试数据验证一条代表性链路。

导入不是数据库恢复工具，也不应承载告警路由等模板 schema 明确排除的对象。

## JSON 配置同步

配置同步用于把当前租户配置导出为 JSON，或把经过检查的 JSON 应用到目标租户。

同步与同步日志入口仅平台管理员可用；租户配置包导入与JSON同步使用各自的接口授权，不能因能导入Excel就推断能执行JSON同步。

1. 在源侧选择环境和最小导出范围；不勾选通常表示导出全部，提交前再次确认。
2. 导出 JSON 并纳入受控变更流程，不在公共渠道传递可能含敏感引用的文件。
3. 在目标侧确认环境和租户，上传或粘贴 JSON。
4. 查看 JSON 合法状态和对象数量。
5. 先预览差异，再执行应用。
6. 应用后查看同步日志与审计记录。

提交超时或返回结果不确定时，保留页面给出的提交身份，先查询提交回执。日志 `RUNNING` 只表示最终结果尚未确认，不证明业务尚未写入；此时暂存的零计数也不代表零成功。确认完成后再核对实际统计，不因响应丢失重新提交相同配置。

当前 JSON 配置同步与 Job Bundle 不再传输独立 Pipeline 定义；旧字段的处理以后端预览结果为准。

跨环境同步时尤其关注 Secret、外部地址、资源队列和环境专属字段。配置同步只处理受支持的控制面对象，不迁移运行实例或执行状态。
