# 作业与流程

> **关注角色**：`ROLE_TENANT_ADMIN`、`ROLE_ADMIN`；`ROLE_AUDITOR` 和 `ROLE_TENANT_USER` 关注查询
> **操作级别**：配置写入；触发、发布或启停可能影响运行
> **典型入口**：准备作业 → 作业定义、工作流定义；文件管理 → 流水线观测

## 对象关系

- **作业定义（Job）**描述可执行业务单元、参数、重试和资源要求。Job 按类型关联系统内置 Pipeline；阶段信息在作业详情中只读展示。
- **Workflow** 是顶层编排与运行入口。新建 Job 会关联受管的单作业 Workflow；组合 Workflow 通过作业节点引用已有 Job。受管的单作业图只读，作业业务配置仍在作业定义维护。
- **系统 Pipeline** 描述 Job 类型对应的内部执行阶段。当前产品不提供独立 Pipeline 定义编辑入口；旧 `/jobs/pipelines` 路由已移除，请从 `/jobs/definitions` 进入作业定义。文件流水线观测仍用于查询实际处理进度。
- **日历、业务日期、窗口与调度配置**约束何时允许形成和执行运行；实际调度和持久化结果以后端为准。

## 新建或修改作业定义

1. 进入“作业定义”，确认当前租户。
2. 填写稳定编码、显示名称、受支持的作业类型和业务参数。新建列表不再提供历史 `WORKFLOW` 包装类型。
3. 配置重试、超时和资源队列；敏感内容使用 Secret 引用。
4. 保存后重新打开详情，核对返回的配置、默认 Workflow 和按作业类型解析的系统阶段。
5. 若需验证，从授权的 Workflow 运行或自助入口发起小范围测试，并在工作流运行和关联作业实例中核对结果。

保存不会让已有运行自动改用新定义。修改生产 Job 前，先检查关联 Workflow、正在运行的实例和后端配置发布规则。

## 打包向导与JSON作业包

打包新建向导、JSON作业包导入和导出仅平台管理员可用；租户管理员可继续使用作业定义的普通新建及编辑。配置包涉及关联Workflow、渠道、模板、资源及告警，权限以实际服务端入口为准。

等待提交期间修改输入、切换租户/账号或关闭重开面板后，旧响应不会关闭当前面板、导航到其他作业或刷新新上下文。进入维护或权限变化后也不会继续使用旧结果；已经发出的业务不会因此撤销，结果不确定时先核对原目标配置，避免重复导入。

切换租户或账号会清空向导中的现有关联选择，需等待当前范围选项加载后重新选择。下一步校验期间重复点击只推进一次；输入或上下文变化后需重新校验。试运行提示对应发送时的模式，不能据当前开关推断先前请求是否写入。

## 使用工作流设计器

1. 从工作流定义列表进入新建或编辑；受管单作业图以只读形式查看。
2. 当前节点库提供开始、结束、作业、网关四类节点。开始和结束是控制节点，不向 Worker 派发普通作业任务。
3. 作业节点引用当前租户内存在且可用的 Job；依赖、输入、失败策略和边条件按页面及后端校验填写。
4. 连接节点，确认有合法的开始路径和可达结束节点；网关分支应满足所选模式的条件与汇合规则。
5. 执行校验，再保存；重新进入画布和 JSON，核对节点、连线与引用已持久化。

切换工作流或离开设计器时，存在未保存内容会要求确认；选择继续编辑会保留当前画布和编辑锁。保存期间继续修改的内容仍标记未保存，需要再次保存；新建成功不会覆盖这些新修改。切换租户会重新加载当前目标，请先保存需要保留的草稿。

历史图若仍含 `FILE_STEP` 或其他已退役节点，应先核对后端迁移/兼容结果；当前设计器会拒绝未知节点类型，不自动把任意旧节点转成合法图。等待、文件检测或审批等业务能力须先核对当前受支持的 Job 类型及后端配置，不能据历史文档推断存在独立的文件步骤或审批节点。

设计器的版本差异页可从已保存的 Workflow 版本中选择比较两端，并读取各自快照；这是定义版本差异，不等同于某次运行的冻结 DAG。需要核对实际执行状态时应打开对应 Workflow 运行详情或完整 DAG。

## 运行与批量触发

工作流列表的运行操作使用明确的业务日期。批量运行最多选择 50 项，每项独立展示受理、结果不确定或明确拒绝；一次点击不保证所有目标都受理。

响应丢失或刷新后出现“结果不确定”时，保留原请求身份并使用页面的只读核对入口。只有明确失败的项可以按页面提示重试；未查到记录不能证明后端没有执行，不要清除记录后更换请求键重复发起。详情与运行恢复的判断见[运行与审批](./runs-and-approvals.md)。

## 变更完成的判断

至少核对以下证据：

- 列表或详情返回新的版本、更新时间或配置内容。
- 关联 Workflow、Job 与系统阶段正确，配置发布或审批状态符合预期。
- 一次受控运行进入预期 Workflow 节点和作业实例；直接开始到结束的控制图不要求产生 Worker 任务。
- 失败、跳过或取消能通过运行详情、Trace ID 和审计解释，不能只以成功提示判断闭环。
