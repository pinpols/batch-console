# 作业与流程

> **关注角色**：`ROLE_TENANT_ADMIN`、`ROLE_ADMIN`；`ROLE_AUDITOR` 和 `ROLE_TENANT_USER` 关注查询
> **操作级别**：配置写入，发布或启停可能影响生产运行
> **典型入口**：作业与流程 → 作业定义、Pipeline、工作流定义

## 对象关系

- **作业定义**描述可执行单元、参数、重试和资源要求。
- **Workflow** 通过节点和连线编排多个步骤、网关、文件步骤或审批节点。
- **Pipeline** 组织文件或数据处理链路，运行进度可在文件观测页面查看。
- **触发器、日历和窗口**决定何时允许产生运行实例。

前端只负责编辑、校验和提交定义；实际调度语义、状态机和执行结果以后端为准。

## 新建或修改作业定义

1. 进入“作业定义”，确认当前租户。
2. 选择新建，填写稳定且可检索的编码、显示名称和任务类型。
3. 配置参数、重试、超时、资源队列等字段。敏感内容应引用 Secret，不直接写入普通参数。
4. 保存前检查必填项和字段提示。
5. 保存后重新打开详情，确认服务端返回内容与输入一致。
6. 需要验证时从授权的自助触发或运行入口发起小范围测试，再到作业运行页确认结果。

修改已在生产使用的定义前，应先确认关联 Workflow、触发器、文件渠道和正在运行的实例。不要把“保存成功”理解为历史实例会自动采用新配置。

## 使用工作流设计器

1. 从工作流定义列表进入新建或编辑。
2. 从左侧节点库拖入开始、结束、作业、网关、文件步骤或审批节点。
3. 连接节点，确保从开始节点可以到达结束节点。
4. 选中节点，在属性区配置引用对象、条件、失败策略和输出。
5. 使用校验功能处理断链、缺少配置、非法条件和重复标识。
6. 保存后返回列表确认版本或更新时间，再按发布流程生效。

### 设计器检查清单

- 只有一个清晰的开始路径，并存在可达的结束节点。
- 网关条件互斥或存在兜底分支，避免数据落入无匹配路径。
- 作业节点引用当前租户内存在且可用的作业定义。
- 文件步骤引用正确的渠道与模板。
- 审批节点的审批对象、超时和失败策略明确。
- 自动布局后仍检查连线方向；布局改善可读性，不改变业务语义。
- 保存前执行校验，保存后重新进入确认画布和 JSON 已持久化。

## Pipeline 维护

Pipeline 修改应围绕输入、处理步骤、输出和失败处理四部分核对：

1. 输入渠道与文件模板是否匹配。
2. 步骤顺序和依赖是否明确。
3. 输出位置、命名与重复处理策略是否正确。
4. 失败后是重试、终止、告警还是进入补偿流程。

上线后从“文件流水线观测”查看到达量、处理中、成功和失败，而不是只看定义页面。

## 变更完成的判断

至少满足以下证据，才可认为配置变更闭环：

- 列表或详情返回新的版本、更新时间或配置内容。
- 配置发布或审批状态符合预期。
- 一次受控测试运行产生实例，并进入预期节点或步骤。
- 失败时可以通过 Trace ID、实例详情或审计记录解释原因。
