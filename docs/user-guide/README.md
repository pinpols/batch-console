# Batch Console 使用指南

> **关注角色**：全部角色
> **文档对象**：平台管理员、平台审计员、租户管理员、租户用户
> **适用范围**：桌面端完整控制台；移动端仅覆盖轻量查询与处置入口

Batch Console 是 File Batch System 的控制面。它用于配置、编排、触发、审批、观测和治理批处理业务，不直接执行作业，也不替代调度器、Worker 或后端审计存储。

## 先确认你的角色

系统采用四类正式角色，按“平台级 / 租户级”和“管理 / 受限访问”两个维度划分：

| 正式角色                       | 作用域     | 主要关注                       | 典型任务                                   |
| ------------------------------ | ---------- | ------------------------------ | ------------------------------------------ |
| `ROLE_ADMIN` 平台管理员        | 跨租户     | 平台配置、租户治理、高风险处置 | 租户管理、全局配置、分片与容量治理、诊断   |
| `ROLE_AUDITOR` 平台审计员      | 跨租户只读 | 合规、变更与运行证据           | 审计记录、配置历史、运行与告警查询         |
| `ROLE_TENANT_ADMIN` 租户管理员 | 当前租户   | 租户内配置与运行管理           | 作业和流程维护、账号管理、审批、文件配置   |
| `ROLE_TENANT_USER` 租户用户    | 当前租户   | 日常观察与受控自助操作         | 查询运行、查看告警、触发授权作业、自助服务 |

系统只接受上述四类正式角色。详细边界见[角色与权限](./roles-and-access.md)。

> 页面是否显示、按钮是否可用，以后端当前会话返回的菜单和接口授权为准。文档中的角色是关注对象和常见授权说明，不替代后端权限校验。

## 通用操作原则

1. **先确认租户**：所有租户级查询和写操作前，核对顶栏当前租户。平台角色切换租户后，列表、统计和详情会重新加载。
2. **先筛选再处置**：运行、告警和投递页面先限定状态与时间范围，再执行重试、取消、确认等动作。
3. **高风险操作先看影响范围**：批次日重放、配置同步、账号停用、密钥撤销等操作可能影响后续任务或其他用户。
4. **保留可关联标识**：问题反馈至少记录租户、业务时间、对象编码、Trace ID 和错误提示；不要在工单或聊天中粘贴密码、Secret 或完整 API Key。
5. **以后端结果为准**：前端成功提示表示请求已被接受，不等于异步作业已经完成。需要回到运行、审批、Outbox 或审计页面确认最终状态。

## 文档边界

- 本指南解释产品操作，不重复工程构建、CI 和部署细节；开发者入口见[前端文档索引](../README.md)。
- 接口字段和权限的权威来源是后端 OpenAPI 与后端授权实现。
- 各环境菜单可能因版本、租户能力或权限不同而减少；这是正常的最小权限表现。
- 截图容易随版本失效，本指南优先使用页面名称、路由和可验证结果描述操作路径。
