## 本轮修复

- 为 Worker、文件中心、通知渠道/规则补充无租户上下文保护，避免管理员或空租户状态误发请求。
- Alert Routing 按后端预留契约改为只读预留态，隐藏无效写操作。
- Excel 配置包上传等待时间调整为 45 秒，匹配真实解析耗时。
- 文件模板和文件渠道在 403/列表失败时保留错误态并清理列表，不再产生未处理 Promise。
- 修正 Observability、诊断和配置运维 E2E 的过期断言、隐藏元素定位和分页等待问题。

## 非阻断项与边界

### 工具链和性能

- 本机 Node 为 v25.4.0，项目约束为 `>=22 <23`；CI/生产构建应统一 Node 22 LTS。
- 构建仍有第三方 pure annotation 和大 chunk 警告；不影响功能验收，后续可单独做拆包优化。
- Outbox 页面在大数据量下曾拉取约 4000 条记录；生产应继续使用服务端分页/筛选，避免运维页面一次性加载过多数据。

### E2E 跳过项

当前 47 个跳过用例主要集中于：Compensation UI 表单、日志自动刷新、通知/Webhook 真写、工作流设计器长链路和移动端写操作；另有按权限或无 Worker 数据条件跳过的用例。它们不阻断当前核心前台上线，但不能计入“所有生产场景已验证”。

### 上线建议

当前结论为“核心功能可灰度上线”，上线前仍应保留后端故障注入、长时真实作业、账期补跑、外部依赖失败恢复和多用户并发运维作为上线监控与后续专项，不应仅凭前端 E2E 宣称生产级容灾和容量已达标。
