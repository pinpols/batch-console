## 4. P1：优先打磨

### FE-POLISH-01 调度快照失败态和危险操作

**已实测问题**

- `/scheduler/snapshot` 的快照接口返回 HTTP 500 时，Toast 消失后主体区域完全空白，用户无法判断是无数据、权限问题还是后端依赖失败。
- “全局暂停”和“全局恢复”同时作为高强调按钮常驻，未根据当前调度状态收敛动作，误操作风险偏高。
- 页面适合展示 `generatedAt` 和租户上下文，但时间必须走统一展示时区格式化。

**建议**

- 增加持久错误态：错误摘要、TraceId、重试按钮、可跳转运维诊断；保留最后一次成功快照并标记为陈旧数据。
- 根据调度状态只展示一个主动作；未知状态时两个动作均禁用并说明原因。
- 危险操作使用二次确认，确认文案明确作用租户和影响范围。

**验收**

- 200 空数据、500、403、超时、恢复成功五种状态都有稳定页面，不出现空白主体。
- 暂停后仅可恢复，恢复后仅可暂停；重复点击不会产生并发请求。

### FE-POLISH-02 综合查询的数据可读性

**已实测问题**

- `/observability/queries` 的“摘要”列直接展示长 JSON，挤压操作类型、Trace、时间和操作列。
- 1440px 桌面视口仍出现操作类型、Trace 和时间被过度截断，用户需要反复 hover。
- 中文界面混用 `Dead Letters`、`Channel`、`Trace` 等词，术语层级不统一。

**建议**

- 摘要列改为结构化摘要：对象名/渠道/回执状态/记录数等 2~3 个关键字段；完整 JSON 放详情抽屉并支持复制。
- 固定状态、时间、操作列的最低可读宽度；长 ID 使用统一短码 + tooltip + 复制。
- 统一文案为“死信”“渠道回执”“链路追踪”，必要的英文协议名放次级说明。

**验收**

- 1366px 视口无需横向滚动即可识别操作类型、结果、操作人、时间和操作。
- 异常 JSON、空摘要、超长值不会撑高表格行或破坏列宽。

### FE-POLISH-03 作业详情 9 Tab 操作闭环

**已实测问题**

- `/jobs/definitions/:id` 的 9 Tab 能正常展示，桌面布局可用，但页头缺少直接“编辑”入口，查看后要返回列表再找同一作业。
- 基本信息仍暴露 `DEPENDSONJOBCODE` 这类原始字段名；审计时间使用原始 ISO 字符串，未走展示时区。
- 基本信息 Tab 同时重复展示调度、资源、审计摘要，与独立 Tab 的信息职责重叠。

**建议**

- 页头增加受权限控制的“编辑”，保留“刷新/演练/手工触发”；低频操作进入更多菜单。
- 所有字段使用产品文案，原始 key 只在 tooltip 或开发信息中出现；时间统一走 `fmtDatetime`。
- 基本信息只保留身份、状态和关键摘要；调度/资源/告警/审计的完整字段归各自 Tab。
- URL 同步当前 Tab，刷新和分享链接后保持上下文。

**验收**

- 9 个 Tab 分别覆盖基本信息、调度、资源、触发、关联文件、关联编排、告警、运行历史、审计。
- `IMPORT/EXPORT`、`WORKFLOW` 和普通作业的条件 Tab 均有明确适用/不适用状态。
- 编辑、演练、触发和跳转关联实体均按角色正确显示或禁用。

### FE-POLISH-04 作业实例详情降噪

**已实测问题**

- `/monitor/job-instances/:id` 的 6 个指标卡重复显示 `instanceStatus`、`bizDate`、`queueCode` 等内部字段名。
- 页副标题直接展示 `R/L/S/Esc` 快捷键说明，占用核心上下文位置。
- “诊断、取消、重跑”等动作在页头和概览区重复出现，主次不清。

**建议**

- 指标卡次级文案改为业务解释或移除；完整 ID 使用复制按钮，不重复占两行。
- 快捷键移入帮助菜单或 tooltip，副标题只保留 Job、业务日和状态。
- 页头保留刷新和主动作，概览区只保留与当前区块相关的跳转；终态动作必须禁用并说明原因。

**验收**

- 首屏能在 5 秒内识别“谁、哪天、什么状态、何时开始/结束、下一步能做什么”。
- 同一动作不在同一视口出现两次；禁用态可解释。

### FE-POLISH-05 调度治理三类配置的层级统一

**已实测问题**

- `/governance/queues`、`/governance/windows`、`/governance/calendars` 复用同一大组件，但页面标题、区块标题和路由命名并不完全一致。
- 队列和日历页重复显示页标题与区块标题；筛选 placeholder 混用中文和 `queueCode / name`。
- 队列表在 1440px 下“更新时间”已被截断，固定操作列进一步压缩信息列。

**建议**

- 将三页表现为同一“调度配置”工作台的分段控制，保留三个可深链 URL；页面标题随子域变化。
- 统一术语为“队列编码/名称”“日历编码/名称”，清理中英混排 placeholder。
- 时间列保证完整显示到秒；低频字段进入列设置，不依赖横向滚动作为默认体验。

**验收**

- 从作业详情进入日历/窗口/队列后，返回仍回到原作业和原 Tab。
- 三个 URL 刷新后选中正确子域；新增按钮、权限和空态随子域正确切换。

### FE-POLISH-06 文件流水线观测由“表格集合”升级为运维视图

**已实测问题**

- `/files/pipeline-obs` 当前是流水线、步骤、投递、错单四张平级表，跨阶段定位需要用户自行拼接信息。
- 表格列较多，Job、Trace、时间在常用桌面宽度下同时截断；选中运行后的阶段耗时和失败位置不够突出。

**建议**

- 首屏增加 RECEIVE → PARSE → VALIDATE → LOAD → ARCHIVE 阶段概览，点击阶段筛选下方运行。
- 使用主从布局：运行列表为主，选中项展示阶段时间线、当前阻塞点、关联实例/文件/Trace 和可执行动作。
- “投递”“错单”改为更明确的“渠道投递”“错误记录”。

**验收**

- 从文件、作业实例或 Trace 带参数进入时，自动定位对应运行并展示上下文。
- 失败运行能直接看到失败阶段、错误摘要和允许的重试入口。

### FE-POLISH-07 隐藏页与二级页统一验收

**源码确认问题**

- 现有 `all-pages-zero-error.spec.ts` 只覆盖部分页面；23 个隐藏入口和上下文二级页没有一份穷尽、可对账的单一清单。
- 多个低频页由专项 E2E 零散覆盖，但不能证明命令面板可达、权限正确、面包屑/返回链路正确。

**建议**

- 建立由 `navigationGroups + router` 自动生成的页面清单测试，避免手工数组继续漂移。
- 每个隐藏页至少验证：命令面板可检索、对应角色可达、非授权角色被拒绝、标题/面包屑正确、空态和错误态不空白。
- 每个详情页至少验证：从列表进入、浏览器返回、显式返回、刷新深链、租户切换后的行为。

**验收**

- CI 对 54 个菜单路径、23 个隐藏标记和二级动态路由做一致性断言。
- 新增路由但未进入自动清单时测试失败。
