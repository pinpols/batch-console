# Workflow 历史版本真实联调

## 范围

核对 Workflow 定义历史版本是否真实持久化、列表和详情 API 是否遵循租户边界、差异页能否比较用户所选版本，以及租户切换期间是否清除旧画布并忽略迟到响应。

## 结果

- 使用 WDI `fix/wdi-current` 前后端代码，临时认证 Console 18181 与 Vite 5181；未重启或改配共享 Console 18080、Orchestrator 18082。Chromium 真实认证场景 1/1 通过，0 重试。
- 真实创建 Workflow 并保存 v1–v4；PostgreSQL 独立读回四份节点快照，版本列表按 `[4, 3, 2, 1]` 返回且当前版本为 v4。
- 读者角色读取所属租户版本返回 200，使用其他租户标识读取返回 403。差异页选择 v2→v3，页面显示节点修改并将选择同步到地址栏。
- 切到第二个临时租户后，原 Workflow 读取返回 404 且差异画布清空；再释放先前租户的延迟响应，旧画布没有恢复。切回原租户后，页面恢复 v2→v3 比较。
- 主租户内定义、节点、边、历史版本、运行记录、审计和账号等夹具清理计数全部为 0；辅助租户行数为 0。临时 Console 与 Vite 均随脚本关闭。

## 验收脚本同步

首次浏览器尝试在比较按钮触发后立即刷新，Playwright 点击动作没有等待 Vue Router 完成异步导航，因而刷新读回旧地址。测试补上地址栏版本对的显式等待后复跑通过。真实用户的版本选择、路由和切租户行为均通过，未发现产品回退。

脱敏后的版本、权限、路由和清理证据见 [real-evidence.json](./assets/workflow-definition-versions-2026-10-26/real-evidence.json)。该结果关闭能力矩阵 G11 的本地真实联调，不代表生产发布验收。
