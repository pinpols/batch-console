## 性能优化

### 1. 消除客户端全量分页拉取

`api/adapters.ts` 中的 `fetchAllPageItems()` 最多拉取 maxPages×200=20000 条记录做客户端过滤，数据量大时会极慢。

**改进方向：** 推动后端在接口中添加 filter query 参数，前端直接传参给后端过滤。这是最高优先级的性能问题。

> ⚠️ 需后端配合，暂未实施。

### 明确存在的代码问题

#### 12.1 统计卡片在切换或首次加载后可能显示错误节点数 / 连线数

- 现象：画布已经有节点，但左侧“节点 / 连线”统计仍可能显示 `0 / 0`
- 代码位置：
  - `src/views/workflow/WorkflowDesigner.vue:904`
  - `src/views/workflow/WorkflowDesigner.vue:1495`
- 根因：`stats` 依赖 `graphVersion` 刷新，但 `resetGraph()` 调用 `graph.resetCells()` 后没有同步递增 `graphVersion`
- 影响：用户会误判当前草稿为空，和截图中的现象一致

#### 12.2 DSL 预览与“复制 DSL”在切换流程后可能保留旧图数据

- 现象：切换 Workflow 或从后端 / 本地草稿加载后，右侧 DSL 预览不一定和画布一致
- 代码位置：
  - `src/views/workflow/WorkflowDesigner.vue:939`
  - `src/views/workflow/WorkflowDesigner.vue:1092`
  - `src/views/workflow/WorkflowDesigner.vue:1495`
  - `src/views/workflow/WorkflowDesigner.vue:2157`
- 根因：`dslPreview` 是 `computed`，但没有显式依赖 `graphVersion`；`graph.resetCells()` 不会触发 Vue 对 X6 内部 cell 变化的响应式更新
- 影响：复制出去的 DSL 可能不是当前画布真实内容，这是设计器里的高风险错误

#### 12.3 通过侧栏修改节点类型可绕过 START / END 唯一性约束

- 现象：拖拽节点时禁止重复创建 START / END，但把已有 TASK 节点改成 START / END 仍然可以成功
- 代码位置：
  - `src/views/workflow/WorkflowDesigner.vue:309`
  - `src/views/workflow/WorkflowDesigner.vue:1891`
  - `src/views/workflow/WorkflowDesigner.vue:1974`
- 根因：唯一性校验只做在拖拽落点校验里，`applyNodeForm()` 没有对 `nodeType` 变更做同样约束
- 影响：页面能生成本应被禁止的非法图，后续只能靠旁路校验提示发现

#### 12.4 本地草稿自动保存缺少异常保护

- 现象：浏览器 `localStorage` 配额满、隐私模式或写入失败时，自动保存会直接抛异常
- 代码位置：
  - `src/views/workflow/WorkflowDesigner.vue:1764`
- 根因：`persistDraft()` 直接调用 `window.localStorage.setItem(...)`，没有 `try/catch`
- 影响：草稿保存失败时页面可能出现未处理异常，且用户看不到明确降级提示

#### 12.5 复制 DSL 缺少剪贴板失败兜底

- 现象：浏览器未授权剪贴板、非安全上下文或系统策略限制时，复制动作会失败
- 代码位置：
  - `src/views/workflow/WorkflowDesigner.vue:2157`
- 根因：`navigator.clipboard.writeText(...)` 没有异常处理
- 影响：操作静默失败，用户无法判断是 DSL 为空还是复制失败

### 易用性 / 用户友好度问题

#### 12.6 全局字号压得过低，不适合长时间编排

- 代码位置：
  - `src/views/workflow/WorkflowDesigner.vue:2335`
  - `src/views/workflow/WorkflowDesigner.vue:2350`
- 现状：页面全局 `font-size: 10px`，部分说明文字是 `9px`
- 问题：信息密度是上去了，但可读性明显下降，尤其是节点属性、校验列表、画布提示和长时间使用场景
- 建议：把主信息层恢复到 `12px ~ 14px`，仅次级说明降一档，避免整个编排器为了“塞更多信息”牺牲识别效率

#### 12.7 面板 hover 缩放会造成控制台式页面的视觉抖动

- 代码位置：
  - `src/views/workflow/WorkflowDesigner.vue:2318`
- 现状：左右卡片 hover 会 `scale(1.02)`
- 问题：这类交互更像展示型页面，不像长时间使用的编排控制台；鼠标移动时会造成视觉漂移
- 建议：保留边框 / 阴影反馈即可，不建议在运维编排页做明显缩放

#### 12.8 当前主要依赖拖拽建图，缺少低摩擦快速插入

- 现状：页面已有拖拽建图，但没有显式的点击添加、快捷键添加、从当前节点快速插入下游节点
- 问题：对于触控板、远程桌面、重度键盘用户不够友好
- 建议：补充“选中节点后快速加下游 TASK / DECISION / JOIN”的快捷入口，以及常用快捷键

#### 12.9 校验结果只有列表，没有和画布联动

- 现状：左侧有校验列表，但没有点击某条问题后自动定位节点 / 高亮边
- 问题：图一大以后，用户只能人工在画布里找问题点
- 建议：校验项支持点击定位、聚焦、临时高亮，并区分错误 / 警告等级

### 从成熟作业 DAG 系统视角，还缺的关键能力

#### 12.10 配置生命周期还没闭环

- 当前页面更像“本地草稿型编排器”，不是“可发布的工作流设计器”
- 证据：`src/api/workflow.ts:38` 里的 `saveDefinition()` / `publishDefinition()` 仍是 reject，占位逻辑未接到后端写接口
- 建议补齐：
  - 保存到后端
  - 服务端校验
  - 发布 / 下线
  - 版本对比
  - 草稿与已发布版本 diff
  - 回滚入口

#### 12.11 缺少成熟设计器应有的编辑效率能力

- 建议补齐：
  - 撤销 / 重做
  - 框选、多选、批量移动
  - 复制 / 粘贴子图
  - 对齐、分布、吸附辅助线
  - 快捷键帮助面板
  - 节点搜索与定位

#### 12.12 缺少前置语义约束，很多错误只能事后发现

- 当前已有基础结构校验，但还不够
- 建议补齐：
  - 连线时即禁止成环，而不是事后报错
  - `DECISION` 节点默认边唯一
  - `CONDITION` 边必须有条件表达式
  - `START` 不允许入边，`END` 不允许出边
  - `JOIN` 节点支持明确 join 模式，而不是仅检查前驱数量
  - 节点关联的 job / pipeline / worker / window 应做存在性校验

#### 12.13 大图治理能力不足

- 现状：页面有小地图，但还缺大图编排常见能力
- 建议补齐：
  - 节点分组 / 子流程折叠
  - 泳道或逻辑分区
  - 上下游链路高亮
  - 失败路径高亮
  - 大图搜索、筛选与视图保存

#### 12.14 缺少运行态辅助，无法支撑“设计 + 运维”一体化

- 成熟系统通常会把设计态和运行态结合
- 建议补齐：
  - 运行实例叠加视图
  - 最近一次运行结果着色
  - 节点耗时 / 重试 / 失败次数 overlay
  - 从节点跳转到实例 / 日志 / 审计 / 文件
  - dry-run / 模拟执行 / 影响分析

#### 12.15 破坏性操作和多人协作保护不足

- 建议补齐：
  - 删除节点 / 连线确认
  - 离开页面未保存提醒
  - 本地草稿与后端版本冲突提示
  - 编辑锁 / 最近编辑人 / 更新时间
  - 操作审计

#### 12.16 读取模式在大租户下会遇到性能瓶颈

- 代码位置：
  - `src/api/workflowQueries.ts:22`
  - `src/api/workflowQueries.ts:28`
  - `src/views/workflow/WorkflowDesigner.vue:1726`
- 现状：先拉全租户 `workflow-nodes` / `workflow-edges`，再前端按 `workflowDefinitionId` 过滤
- 问题：租户数据一大，设计器首次打开和切换流程都会越来越慢
- 建议：后端提供按 `workflowDefinitionId` 或 `workflowCode` 精确查询的接口，前端停止全量聚合

#### 12.17 缩略图语义仍然不对，显示的是“内容 fit 预览”，不是“当前视口在大画布中的位置”

- 代码位置：
  - `src/views/workflow/WorkflowDesigner.vue:1299`
  - `src/views/workflow/WorkflowDesigner.vue:2106`
  - `src/views/workflow/graph/FixedMiniMap.ts:74`
- 现状：
  - 主画布使用的是 `Graph + autoResize + panning`
  - 缩略图使用 `FixedMiniMap`
  - `FixedMiniMap` 会基于内容包围盒做 `zoomToRect(...)`
- 问题：
  - 这本质上仍然是“围绕当前内容做缩放后的概览”
  - 不是一个有固定 world bounds 的“大画布视口指示器”
  - 所以节点少、图小、或刚自动布局后，缩略图里的节点仍会显得偏大，不能稳定表达“当前图在大画布里的位置”
- 结论：
  - 这是实现语义问题，不是简单调一下缩略图尺寸就能彻底解决
- 建议：
  - 方案 A：引入 X6 `Scroller`，定义明确的工作区 / world bounds，让 MiniMap 直接表达可视区域与大画布关系
  - 方案 B：保留当前无 scroller 模式，但自己维护固定世界坐标系，缩略图按世界坐标渲染，而不是按内容包围盒 `fit`
  - 如果不改语义，只继续调 `MIN_OVERVIEW_W/H` 或 margin 系数，问题只会缓解，不会消失

### 建议的落地优先级

1. 先修真实错误：统计卡片、DSL 预览、节点类型唯一性、草稿异常兜底
2. 再补配置闭环：保存、校验、发布、版本 diff
3. 然后补编辑效率：撤销重做、多选、搜索定位、校验联动
4. 最后做运行态增强：实例叠加、影响分析、大图治理

### 14.2 Bug（补充审查）

#### B1 `submitToBackend` 缺少显式 catch

- 位置：`src/views/workflow/WorkflowDesigner.vue:2344-2371`
- 说明：
  - 当前 API 失败时，拦截器会弹错误 toast，`finally` 只负责复位 loading
  - 当前实现并不会在失败时误删草稿
  - 但成功提示、草稿删除、`loadWorkflow()` 刷新都在同一成功路径里，缺少显式 `catch` 仍然会让异常分支不够清晰
- 建议：
  - 增加 `catch`，明确区分“提交失败”“提交成功但刷新失败”两类情况

#### B2 `applyEdgeForm` 用 `cell.id` 覆盖 `data.id`

- 说明：

  - 当前不再作为未解决问题

#### B3 `copyDsl` 在预览面板关闭时复制空串

- 说明：
  - 该问题已在本轮会话内修复
  - 当前不再作为未解决问题

#### B4 `readDraft` 对草稿结构升级缺少显式校验

- 位置：`src/views/workflow/WorkflowDesigner.vue:2251-2262`
- 问题：
  - `JSON.parse` 成功但结构过期时，仍会被直接 cast 成 `WorkflowDraftPayload`
  - 旧版草稿可能导致节点 / 连线结构异常，但用户看不到明确提示
- 建议：
  - 解析后补基础 schema 校验
  - 若结构不合法，提示“草稿结构已过期，将回退到后端数据”
  - 同时清理本地草稿

#### B5 `loadWorkflow` 的竞态检查时机仍可更早

- 位置：`src/views/workflow/WorkflowDesigner.vue:2183-2237`
- 问题：
  - 当前虽已有 token 机制，但异步返回后的检查点仍可继续前移
  - 在多次快速切换 workflow 时，过期请求返回值仍可能在局部流程里参与判断
- 建议：
  - 在每个 `await` 返回后立刻执行一次 token 校验
  - 尤其是在 definitions 查询完成后、nodes/edges 查询完成后立即校验

#### B6 `validateGraph` 需要确认端点比对使用业务字段，而非 X6 内部标识

- 审查关注点：
  - 若校验逻辑拿 `getSourceCellId()` / `getTargetCellId()` 与 `nodeCode` 做对比，会存在内部 id 与业务 id 混用风险
- 建议：
  - 校验统一基于 edge data 内的 `fromNodeCode` / `toNodeCode`
  - 避免依赖 X6 内部 cell id 参与业务语义判断
